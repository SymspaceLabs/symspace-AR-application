# Hosted / commercial alternatives and capture methods for AR-ready 3D product models (state as of 2026-10-07)

Scope note for the report writer: this file covers (1) hosted generative-3D APIs, (2) AI-plus-human and pure-human modelling services, (3) photogrammetry / scanning for true metric scale, (4) hybrid scan+AI workflows, and (5) licensing/terms. It is meant to be compared against the prior report's open-source choice (TRELLIS.2 / Pixal3D, with immature open auto-rigging).

## Key Question 1: Hosted generative 3D APIs (2026 state) — features, formats, scale, rigging, pricing, turnaround

### Takeaway
By October 2026 the four production-grade hosted image-to-3D APIs are Tripo (v3.x / P-series with native quad topology, auto-rig, retopology, and an `autoSize` real-world-metres option), Meshy (6/7, auto-rig, remesh, cheap credits), Rodin/Hyper3D (Gen-2 / Gen-2.5, up to 5 input images, quad-dominant mode, an explicit `bounding_box` size constraint), and Tencent Hunyuan 3D 3.1 (up to 8-view input, 4K PBR, offered on Tencent Cloud international regions and third-party hosts). Per-asset costs are roughly $0.15–$1.50 for a textured model and $0.05–$0.25 extra for auto-rigging; none of the vendors offers a human-verified "AR-commerce-ready" guarantee, and real-scale support exists only as a model-side heuristic (Tripo `autoSize`) or a user-supplied box (Rodin `bounding_box`), not as a measured value.

### Inferences
- Effective per-asset API cost for a textured image-to-3D model, using the vendor-stated credit tables and credit prices: Tripo ≈ 30 credits × $0.01 = **~$0.30** for a draft model, plus ~$0.05–$0.40 for retopology/quad/smart-lowpoly and ~$0.20–$0.25 for rigging; Meshy-6 ≈ 30 credits (credit→USD unverified; third-party reseller quotes ~$1.20 for Meshy 7 textured); Rodin ≈ $0.80/request on a reseller or $1.50/credit direct; Hunyuan 3.1 Rapid ≈ $0.225/model on a reseller. All are one to two orders of magnitude cheaper than a human-made model ($60–$800) but with no quality guarantee.
- Only two vendors expose anything about real-world size: Tripo (`autoSize`, an AI guess in metres) and Rodin (`bounding_box`, user-supplied). For Symspace, the reliable path is to keep the client-entered dimensions and rescale the GLB in the pipeline regardless of vendor, exactly as with the open-source pipeline.
- Hosted auto-rigging (Tripo Rig, Meshy rigging, KIRI "auto rig") targets humanoid/creature characters; no vendor advertises garment-specific rigging or wearable attachment points. The prior report's finding that open auto-rigging is immature is not solved by hosted services; it is only cheaper to try.
- Quad topology is now a differentiator (Tripo P2.0 native quad; Rodin quad-dominant; Hunyuan 3.1 quad; Tripo "Smart Mesh" retopology). Quad output is directly relevant to Shopify's "four-sided geometry" requirement.

## Key Question 2: AI-plus-human hybrid and pure-human modelling services — pricing per SKU, turnaround, AR-readiness

### Takeaway
Human-in-the-loop services cost roughly $60–$800 per SKU (Modelry from $60/model; Kaedim ~$20/credit on $400–$1,200/month plans; agency/freelance $200–$800) with turnaround from ~39 hours (Kaedim's claim) to several days or ~3 weeks (Amazon's free scan-plus-artist programme), and they are the only route that explicitly promises platform-spec compliance (GLB/USDZ, real size, QA). Hexa (Amazon's partner) and 3D Cloud do not publish prices.

## Key Question 3: Photogrammetry and scanning for true metric scale — tools, scale mechanisms, quality for commerce, capture burden

### Takeaway
Metric scale comes "for free" only from LiDAR/depth-assisted capture (Apple Object Capture via `ObjectCaptureSession` on iPhone 12 Pro+ / LiDAR iPads, and LiDAR modes in Polycam/KIRI/Scaniverse) or from scale markers in desktop pipelines (RealityScan/COLMAP + ArUco); pure photo-only photogrammetry and all generative models are scale-ambiguous. Apple recommends a minimum of ~100 images with 70 % overlap for Object Capture, which is a heavier ask than "20–50 photos," and reflective jewelry/eyewear defeat photogrammetry without matte spray or cross-polarised lighting.

## Key Question 4: Hybrid workflows — scan/photo-set for scale and geometry, AI (multi-view) to fill the back; evidence that multi-image conditioning reduces hallucination

### Takeaway
Multi-view conditioning is now standard in hosted models (Rodin Gen-2: up to 5 images; Hunyuan 3D 3.1: up to 8 views; open Hunyuan3D-2mv: front/left/back/right), and vendors state it improves reconstruction accuracy, but no independent quantitative evidence that it reduces back-side hallucination on commerce products was found; TRELLIS.2 is documented only as single-image.

### Cited Findings
- Rodin Gen-2 "accepts up to five input images of the object, with multiple images acting as multi-view references" — [Runware Rodin Gen-2 guide](https://runware.ai/docs/models/hyper3d-rodin-gen-2/guides/image-and-text-to-3d).
- Hunyuan3D 3.1 "reconciles data from up to eight reference images (front, back, left, right, top, bottom, and 45-degree left/right angles)" — [3D AI Studio Hunyuan3D 3.1](https://www.3daistudio.com/Models/Hunyuan3D-3-1); "Tencent HY 3D 3.1 ... supports 8-view input" (global platform launch) — [ToolNavs](https://toolnavs.com/fr/article/1123-tencent-hy-3d-31-is-launched-on-the-global-platform-and-supports-8-view-input).
- Open Hunyuan3D-2mv in ComfyUI: the `Hunyuan3Dv2ConditioningMultiView` node "taking optional front, left, back, and right view embeddings and combining them with positional encoding"; a ComfyUI tutorial says it "integrates multiple image perspectives to enhance the 3D reconstruction accuracy" — [ComfyUI docs node](https://docs.comfy.org/built-in-nodes/Hunyuan3Dv2ConditioningMultiView); [Comfy workflow: HY 3D 2.0 MV](https://comfy.org/workflows/3d_hunyuan3d_multiview_to_model-0cd2d1919edc/).
- Hunyuan3D 1.0 paper ablation (single-image, not multi-view): "traditional fixed CFG tended to generate dark shadows in back views, and adaptive CFG was used to dynamically adjust CFG according to viewpoint distance" — [Hunyuan3D 1.0 (arXiv 2411.02293)](https://arxiv.org/pdf/2411.02293). This documents that back-view degradation is a known failure mode for single-image conditioning.
- TRELLIS.2 is described as "a 4B-parameter model capable of generating high-fidelity, fully textured 3D assets from a single image" with "stronger consistency across different viewing angles" — [PiAPI: TRELLIS 2 vs TRELLIS](https://piapi.ai/en/blogs/trellis-2-vs-trellis-3d-generation-api); [trellis2.app how-to](https://trellis2.app/blog/how-to-use-trellis-2); [ComfyUI TRELLIS.2 tutorial](https://docs.comfy.org/ja/tutorials/3d/trellis2.md). No multi-image input is documented in these sources.
- Tripo's image-to-model API offers multi-view input per its docs index ([developers.tripo3d.com introduction](https://developers.tripo3d.com/en/docs/introduction.md)) — page blocked; **unverified detail**.
- Apple's pipeline is the inverse hybrid: ObjectCaptureSession provides LiDAR-derived scale and poses, reconstruction stays photogrammetric — [Apple forums 840946](https://developer.apple.com/forums/thread/840946).
- A third-party Apify actor advertises "Product Photo to 3D Model with Real-World Scale" built on Tripo — [Apify toolsheder/photo-to-3d](https://apify.com/toolsheder/photo-to-3d) — evidence of demand but not a primary capability.

### Inferences
- A practical hybrid for Symspace: ask clients for 3–6 photos (front/back/left/right ± top/bottom) plus dimensions; feed to a multi-view model (Hunyuan 3.1 8-view or Rodin 5-image hosted; Hunyuan3D-2mv open) so the back is observed rather than hallucinated; then rescale to the client dimensions. This is cheaper and more client-feasible than a 100-image scan, and uses the same dimension field the pipeline already needs.
- Because TRELLIS.2 is single-image per the available sources, the open-source multi-view fallback is Hunyuan3D-2mv (open 2.x weights), with the 1M-MAU licence cap noted in Key Question 5.
- For geometry-critical items (shoes, bags) a LiDAR Object Capture scan can serve as ground truth and the AI model used only for texture/back-side completion, but no off-the-shelf tool fuses a scan with a generative model; that would be custom engineering.

### Gaps
- No peer-reviewed or vendor benchmark quantifying hallucination reduction from multi-view vs single-view conditioning on product objects was found (searches on TRELLIS.2 multi-image evaluation and Hunyuan3D-2 multi-view ablation returned only implementation docs).
- Whether TRELLIS.2 or Pixal3D accept multiple views could not be confirmed from accessible sources.
- Tripo multi-view API parameters (number of views, credit cost) not verified.
