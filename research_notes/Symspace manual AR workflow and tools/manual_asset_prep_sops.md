## KQ1. Blender-based SOP (free): import, scale, origin, axes, named anchor Empties, extras, cleanup, add-ons, time per asset

### Takeaway
Blender (4.5 LTS / 5.x) with the bundled Khronos glTF add-on is sufficient for the whole non-rigged pipeline: metres are native, "Apply" transforms + "Set Origin" give the pivot, the exporter's "+Y Up" option handles the Z-up→Y-up conversion, Empties become glTF nodes, and the "Custom Properties" export option writes Blender custom properties into glTF `extras`. Validation can be done free with 3D-Print Toolbox, Khronos glTF Validator, glTF-Transform `inspect`, and the Khronos glTF Asset Auditor.

### Cited Findings

**Versions (Blender / glTF add-on)**
- The Khronos glTF-Blender-IO README states "4.5.x is the current Blender LTS release", "5.0 is the current stable release", "5.1 is the next stable release", and the main branch "will become Blender 5.2"; it also states "Blender 2.80 and higher bundle this addon in the main Blender install package, so no 3rd-party install is required." — [glTF-Blender-IO README](https://github.com/KhronosGroup/glTF-Blender-IO)
- The add-on's current `__init__.py` on `main` declares version `(5, 3, 36)` and a Blender requirement of `(5, 3, 0)`, i.e. the development branch now targets Blender 5.3 (so the README's "will become 5.2" line is stale). — [io_scene_gltf2/__init__.py (raw)](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py)
- Blender 5.0 was released in November 2025 (snippet; page blocked). — [OSArch: Blender 5.0 released](https://osarch.org/2025/11/18/blender-5-0-released/)
- Community blog (unverified, treat as opinion): Blender 5.0 made glTF "a recommended path for static assets, including Draco mesh compression with better default settings" and KHR_materials_variants; a later post claims "the glTF exporter later gained meshopt compression (EXT_meshopt_compression…) in Blender 5.2 LTS, which shipped on July 14, 2026", and that Collada was removed and a C++ FBX importer became default in 5.0 (snippets). — [StraySpark blog](https://www.strayspark.studio/blog/blender-5-1-features-game-developers-spring-2026); [Cinevva guide](https://app.cinevva.com/guides/blender-5-for-game-artists)

**Axis / unit conventions across Blender → glTF → Unity**
- glTF: "In glTF 1 unit = 1 meter"; "The size of the model must be 1:1 the size of the real item"; both glTF and USDZ "use the right-handed coordinate system"; products should be "positioned upright and forward for the best presentation". — [Khronos 3DC Asset Creation Guidelines v2](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md)
- Apple's body-tracking docs state the required export convention is "+Y for up, +Z for forward, and +X for right" and "Your model also must face forward on the +Z axis" (same convention glTF uses for "forward"). — [Apple: Validating a Model for Motion Capture](https://developer.apple.com/documentation/arkit/validating-a-model-for-motion-capture)
- UnityGLTF converts handedness by inverting X: the SchemaExtensions.cs comment (quoted in search results) says glTF uses "+Y up, +Z forward, -X right (right-handed)", Unity uses "+Y up, +Z forward, +X right (left-handed)", and UnityGLTF "converts handedness by multiplying by a negative X scale" (snippet). An old issue notes other engines (Babylon) instead flip Z and rotate 180° about Y. — [UnityGLTF issue #257](https://github.com/KhronosGroup/UnityGLTF/issues/257)
- Shopify's checklist: "The model must use real-world scale … measured in meters as specified in the glTF standard" (snippet). — [Shopify 3D model standards checklist](https://help.shopify.com/partners/resources/creating-3d-models/3d-model-standards-checklist)

**Origin / pivot practice**
- Khronos: "The general recommendation is for the bottom center of the product to be placed at 0,0,0"; alternative anchoring points per category, e.g. "top-center for a ceiling-mounted product". — [Khronos 3DC Guidelines v2](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md)
- A Blender→glTF studio checklist (snippet): "all transforms need to be applied" (Object ▸ Apply ▸ All Transforms), "Origins should be set to bottom-center", and the scripted export uses `bpy.ops.export_scene.gltf(... export_apply=True)`. — [GMetri: Export GLB/GLTF from Blender](https://docs.gmetri.com/Guidelines/Content_Guidelines/export-GLTF-from-blender)
- glTF-Transform's CLI can fix the pivot post-export without Blender: `center <input> <output> --pivot <center|above|below>` — "Center the scene at the origin, or above/below it" ("above" = bottom-centre on the floor). — [glTF-Transform cli.ts](https://github.com/donmccurdy/glTF-Transform/blob/main/packages/cli/src/cli.ts)

- Vendor claim: Tripo "Smart Mesh P1.0" emits low-poly structured topology at generation time ("full pipeline … approximately 3 minutes 5 seconds") (snippet). — [TheToolNerd](https://www.thetoolnerd.com/p/tripo-smart-mesh-p10-step-by-step-guide)

### Inferences
- Recommended Blender SOP (ordered): (1) File ▸ Import ▸ glTF 2.0; (2) Scene units Metric, Unit Scale 1.0; (3) size with the N-panel Dimensions to the spec sheet, then Ctrl+A ▸ All Transforms; (4) verify with MeasureIt or the 3D-Print Toolbox "scale to bounds"; (5) set the 3D cursor to the desired pivot (bottom-centre: snap cursor to selected after selecting the bottom vertex loop; wearables: place cursor at the contact point) then Object ▸ Set Origin ▸ Origin to 3D Cursor; (6) rotate so the product's "front" faces Blender −Y (Blender front view), because the exporter's "+Y Up" rotation maps Blender −Y to glTF +Z (Z-up→Y-up rotation; inferred from the add-on option and the glTF/Apple +Z-forward convention — not quoted from the manual, which was blocked); (7) add Empties named per the config contract (`anchor_*`), parent them to the product root, zero their rotation unless the contract needs an axis; (8) add custom properties (Object Properties ▸ Custom Properties) e.g. `category`, `front_axis`, `real_height_m`; (9) Export glTF 2.0 ▸ Format GLB, Include ▸ Custom Properties ON, Transform ▸ +Y Up ON, Mesh ▸ Apply Modifiers ON, Material ▸ Images = automatic/JPEG where lossless not needed, Compression (Draco) OFF unless the Unity importer in use supports it (UnityGLTF Draco support needs the Draco package; see KQ2 gaps).
- Because UnityGLTF flips X rather than Z, an asset whose "front" is glTF +Z will still face Unity +Z (Unity's `transform.forward`), but anything that depends on left/right (left shoe vs right shoe, left earring) is mirrored across X. Name attachment nodes by anatomical side (`anchor_shoe_left`) and verify in Unity rather than trusting glTF +X/−X.
- Cleanup order that fits AI meshes: Merge by Distance → delete loose/floating shells (Select ▸ Select Loose / `trimesh.split`) → 3D-Print Toolbox "Make Manifold" → Decimate (Collapse) or Remesh (Voxel then QuadriFlow / Instant Meshes externally) only if the target budget requires it → re-bake base colour/normal from the original high-poly to the new UVs (Cycles bake; Simple Bake is a paid helper) → materials to a single Principled BSDF per material with Base Colour, Metallic/Roughness packed and Normal maps.
- Realistic time budget per non-rigged asset given the vendor numbers above: 20–60 min for props/furniture/jewellery that only need scale, pivot, anchors and light cleanup; +30–60 min if retopo/bake is needed; garments are hours (KQ4).

## KQ2. Unity-Editor-based SOP: UnityGLTF import, AR-ready prefab templates, pivot wrappers, Humanoid, ARKit joints, Addressables, config export, XR Simulation

### Takeaway
UnityGLTF (Khronos) supports editor import of .glb placed in Assets (with Legacy / Mecanim / Humanoid animation choices) and runtime import via `GLTFSceneImporter`/`GLTFComponent`; Unity's own glTFast is the alternative with a documented Inspector import-settings panel. AR Foundation samples ship a 91-joint ARKit skeleton prefab + `BoneController` that can be copied as the garment-retarget template; Unity 6.3 LTS (Dec 2025) with AR Foundation 6.3/6.4 is current, and 6.2 is no longer supported.

### Cited Findings
- UnityGLTF: "Please use Long-Term Support versions of Unity (2021.3+, 2022.3+, 6000.0+)"; install via Needle package registry or UPM git URL `https://github.com/KhronosGroup/UnityGLTF.git`; Editor import = place `.gltf`/`.glb` (plus `.bin`/textures) in project assets; runtime import via `GLTFComponent` or `GLTFSceneImporter` (`LoadSceneAsync()`, `LastLoadedScene`); animation import "Legacy, Mecanim, or Humanoid"; export menu "Export selected as GLB/glTF"; URP fully supported, Built-in supported, HDRP "limited"; limitations: blend-shape in-betweens not exported, multiple scenes limited. — [KhronosGroup/UnityGLTF](https://github.com/KhronosGroup/UnityGLTF)
- UnityGLTF README (main) lists supported KHR extensions incl. `KHR_lights_punctual`, `KHR_texture_transform`, `KHR_materials_transmission`, `KHR_materials_volume`, clearcoat/sheen/iridescence; "Linear colorspace" recommended. — [UnityGLTF README (raw)](https://raw.githubusercontent.com/KhronosGroup/UnityGLTF/main/README.md)
- glTFast (Unity's package) editor import: move/copy glTF files into Assets (keep `.bin`/images in relative paths), "Select a glTF in the Project view to see its import settings and eventual warnings/errors in the Inspector", expand it to see Scenes/Meshes/Materials/AnimationClips/Textures (snippet). — [Unity glTFast 6.2 ImportEditor](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.2/manual/ImportEditor.html)
- Unity 6.3 LTS "is now available as of December 4, 2025" (snippet). — [Unity blog](https://unity.com/blog/unity-6-3-lts-is-now-available)
- "Unity 6.2 Update release is now no longer supported"; AR Foundation 6.3.2 is the released version for Editor 6000.3 and AR Foundation 6.4 is also available (snippets). — [Unity Manual: AR Foundation package](https://docs.unity3d.com/Manual/com.unity.xr.arfoundation.html)
- AR Foundation Samples: main branch "supports AR Foundation 6.3 and is compatible with Unity versions 6000.0 and newer" (one fetch read "6.4"), with a branch table for Unity 6.5 beta / 6.4 / 6.3 LTS / 6.0 LTS / 2022.3; platforms Android (ARCore), iOS (ARKit), Meta Quest, Android XR. — [arfoundation-samples README](https://github.com/Unity-Technologies/arfoundation-samples)
- AR Foundation body tracking (manual 6.1, snippet): "For 2D detection, humans are represented by a hierarchy of seventeen joints … For 3D detection, humans are represented by a hierarchy of ninety-three joints with world-space transforms" (note: sample code and ARKit use 91 — see below); add `ARHumanBodyManager` to the XR Origin; properties Pose 2D, Pose 3D, Pose 3D Scale Estimation, Human Body Prefab. — [AR Foundation body tracking](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.1/manual/features/body-tracking.html)
- Samples `BoneController.cs`: `k_NumSkeletonJoints = 91`; `JointIndices` enum Root=0, Hips=1 ("parent: Root [0]"), LeftFoot=4, LeftToes=5, RightFoot=9, RightToes=10, LeftHand=22, Neck1=47, Head=51, RightHand=66; bones are matched by name via `Enum.TryParse(jointName…)` ("named as per the JointIndices enum"); pose applied as `bone.transform.localPosition = joint.localPose.position; bone.transform.localRotation = joint.localPose.rotation`. — [BoneController.cs](https://github.com/Unity-Technologies/arfoundation-samples/blob/main/Assets/Scripts/Runtime/BoneController.cs)
- Samples `HumanBodyTracker.cs`: `Instantiate(m_SkeletonPrefab, humanBody.transform)` — the skeleton prefab is parented under the `ARHumanBody` trackable, then `boneController.InitializeSkeletonJoints()` / `ApplyBodyPose(humanBody)`. — [HumanBodyTracker.cs](https://raw.githubusercontent.com/Unity-Technologies/arfoundation-samples/main/Assets/Scripts/Runtime/HumanBodyTracker.cs)
- Unity Humanoid avatar (old 2017.4 manual, concept unchanged; snippet): the Avatar "represents the mapping between the simplified humanoid bone structure understood by Unity and the actual bones"; "the model is in T-pose"; if "Character not in T-Pose" use "Enforce T-Pose"; per-muscle settings are editable. — [Unity Manual: Configuring the Avatar](https://docs.unity3d.com/2017.4/Documentation/Manual/ConfiguringtheAvatar.html)
- UnityGLTF search-result summary: "no explicit coordinate conversion notes" in README; conversion is in `SchemaExtensions.cs` (negative X scale). — [UnityGLTF issue #257](https://github.com/KhronosGroup/UnityGLTF/issues/257)

### Inferences
- "AR-ready prefab template" structure that satisfies the config contract and both importers: `<Category>_Template` (root, identity transform, `ARProductConfig` MonoBehaviour) → `PivotWrapper` (empty child whose local offset cancels the imported model's pivot so that the root sits at the contract pivot) → imported glTF scene instance → anchor children (`anchor_*`, either found by name from the glTF node tree or created by hand). Make prefab variants per SKU from the template so anchor names/scripts are inherited. Pivot correction via a wrapper is necessary because neither UnityGLTF nor glTFast lets you re-pivot on import; use glTF-Transform `center --pivot above` upstream if you want the file itself fixed.
- A small Editor script (`[MenuItem]`) can walk the prefab, read anchor transforms, bounds (`Renderer.bounds` in root space), and the `extras`-derived fields, and write the config JSON; UnityGLTF does not expose `extras` in its README, so either read them from the glTF JSON with a tiny parser before import or re-enter them as prefab fields (see Gaps).
- For ARKit body-driven garments, the cheapest path is to reuse the samples' 91-joint skeleton prefab names (ARKit naming) as the garment rig, so `BoneController` drives it directly without Humanoid retargeting; Humanoid is only needed if the garment is rigged to a different skeleton (Mixamo/Rigify) and you retarget via Animator.
- Addressables / XR Simulation: no AR-specific findings were sourced; standard practice is to mark each product prefab Addressable and load by key; AR Foundation's XR Simulation covers planes/images but not ARKit face/body tracking, so face/body categories need device builds (inference; see Gaps).

### Gaps
- AR Foundation 6.2/6.3 face-tracking manual (ARFace eye transforms, `ARFaceManager`, prefab), XR Simulation feature matrix, Addressables docs and the current Unity Humanoid avatar page could not be fetched (docs.unity3d.com blocked); search budget ran out before snippets were obtained.
- Whether UnityGLTF (editor import) exposes glTF `extras` on imported GameObjects is not documented in the README fetched; verify in the importer source (`GLTFSceneImporter`) or use glTFast's `ImportSettings`/extras callbacks.
- The 91 vs 93 joint discrepancy (sample code vs manual snippet) should be checked against the AR Foundation 6.3 manual.
- UnityGLTF Draco import support (requires the `com.unity.cloud.draco` package) is remembered from prior knowledge but was not verified here.

## KQ3. Category specifics with numbers (ring, watch, glasses, earrings, necklace, shoes, hat, furniture, wall art)

### Takeaway
Industry try-on platforms converge on: real-world scale (metres in glTF, centimetres in Lens Studio), pivot at the attachment/contact point for wearables and bottom-centre for floor items, and an explicit forward axis; the strongest published numeric specs come from Khronos (floor items), WANNA/Snap (shoes, eyewear, earrings, rings, wristwear) and ARKit docs (face-anchor origin behind the face, body-anchor origin at the hips).

### Cited Findings

**Ring**
- US size 7 = inside diameter 17.3 mm, inside circumference 54.4 mm (snippet; full table pages were blocked). — [Jewelers Touch: ring size inner diameter](https://www.jewelerstouch.com/blogs/news/ring-size-inner-diameter)
- Snap Ring Binding Component "binds ring objects to the fingers with the help of reference points pinned to the surface of the hand mesh"; the component "must be placed within the Perspective camera, with a ring mesh inside it as a child"; options: hand (2), finger (5 per hand), finger section ("2 sections on thumb, 3 sections on other fingers, where proximal is the closest to the palm and distal is the furthest"); "The ring's offset position, rotation and scale in relation to the target joint can be modified" (snippets). — [Snap: Ring Binding Component](https://developers.snap.com/lens-studio/features/try-on/ring-binding-component)
- Lens Studio "uses centimeters as its units for both scale and position", and warns some models "may have been normalized to have a scale of 1,1,1 before importing" (snippet). — [Snap community](https://community.snap.com/snapar/discussion/comment/3035)

**Watch / bracelet**
- Case diameter guidance: "36-40mm is the classic mid-size, and 42-46mm wears large"; lug-to-lug examples "a 41mm Submariner has a lug-to-lug of roughly 47.6mm, while a 42mm Sky-Dweller runs closer to 50.5mm"; thickness "around 10-12mm" elegant, "over 14mm" rugged (snippets). — [Bob's Watches case sizes](https://www.bobswatches.com/more/rolex-watch-case-sizes); [Real Men Real Style](https://www.realmenrealstyle.com/watch-size/); [WatchScanning size guide](https://www.watchscanning.com/guides/watch-size-guide/)
- Snap Wristwear Try-On: a "Wrist Binding SceneObject" with "Left Wrist and Right Wrist Scene Objects"; "custom meshes must be oriented the same way as the example models"; workflow = delete the example Watch, import, parent the mesh under Left/Right Wrist, then adjust Transform "to position it similar to the example models" (snippets). — [Snap: Wristwear Try-On](https://developers.snap.com/lens-studio/features/try-on/wristwear-try-on)
- WANNA publishes a dedicated "watches positioning guide" (not fetchable). — [WANNA watches positioning guide](https://wanna.helpjuice.com/watches-category/watches-positioning-guide)

**Glasses**
- Frame size "52-18-140" = lens width 52 mm (typical range "40–60 mm"), bridge 18 mm ("roughly 14–24 mm"), temple 140 mm ("120 to 150 mm", measured hinge to tip); sizes are "printed on the inside of the left temple arm" (snippets). — [Warby Parker: frame sizes explained](https://www.warbyparker.com/learn/eyeglass-frame-sizes-explained); [All About Vision](https://www.allaboutvision.com/eyeglasses/faq/eyeglass-frame-size.htm)
- ARKit face anchor: "Units of face coordinate space are in meters, with the origin centered behind the face"; "The coordinate system is right-handed—the positive x direction points to the viewer's right (that is, the face's own left), the positive y direction points up (relative to the face itself…), and the positive z direction points outward from the face (toward the viewer)". — [Apple: ARFaceAnchor](https://developer.apple.com/documentation/arkit/arfaceanchor)
- `leftEyeTransform`: translation "indicates the position of the center of the eyeball, relative to the position represented by the anchor's transform. The positive z-axis points from the center of the eyeball in the direction of the pupil" (snippet). — [Apple: leftEyeTransform](https://developer.apple.com/documentation/arkit/arfaceanchor/lefteyetransform)
- Apple's face sample ships `ARFaceGeometry.obj` — "ARKit's face geometry in a neutral pose. You can use this as a template to design your own 3D art assets for placement on a real face" — and describes glasses + occlusion geometry: "if you place an occlusion geometry and virtual glasses on the user's face, the face can obscure the frame of the glasses" (depth-only material, `renderingOrder = -1`). — [Apple: Tracking and visualizing faces](https://developer.apple.com/documentation/arkit/tracking-and-visualizing-faces)
- ARFaceGeometry has 1220 vertices with constant topology; a community tutorial uses vertex index 9 (nose) as an attachment point (snippets). — [Apple: ARFaceGeometry.vertices](https://developer.apple.com/documentation/arkit/arfacegeometry/vertices-fhdb); [Kodeco tutorial](https://www.kodeco.com/5491-avplayer-tutorial-for-ios-getting-started?page=2)
- Snap Eyewear Try-On: glasses attach via a Head Binding; "In Try-On mode, glasses automatically resize to match the user's face. With True Size mode enabled, the glasses will keep their original 3D model size of 1 unit = 1 cm"; the Head Binding "comes with a Face Occluder as a child … it represents your user's head in the scene" (snippets). — [Snap: Eyewear Try-On](https://developers.snap.com/lens-studio/features/try-on/eyewear-try-on); [Snap: Head Attached 3D Objects](https://developers.snap.com/lens-studio/features/ar-tracking/face/head-attached-3d-objects)

### Inferences
- Ring: model the hole as a true cylinder of the target size (e.g. US 7 → Ø17.3 mm); put the origin on the hole's axis at the band's mid-plane; name the Empty `anchor_ring_axis` with its local +Y (or the contract's finger axis) along the hole axis — this mirrors Snap's "offset relative to the target joint" model. Head/stone should face glTF +Z (or +Y "up" when the hand is palm-down — the contract must pick one).
- Watch: origin at the case-back centre (contact with the wrist) with dial normal = contract "up"; band loop centred on the wrist axis; Snap's "orient like the example model" rule means the team must publish one reference watch GLB as the orientation template.
- Glasses: origin at the nose-bridge pad contact point; temples along −Z (away from the viewer) since ARKit face +Z points toward the camera; eye-centre spacing from `leftEyeTransform`/`rightEyeTransform` can be used to validate lens centres; the nose-bridge offset from the ARKit anchor origin ("centered behind the face") must be measured per team on the `ARFaceGeometry.obj` template — Apple publishes no number.
- Earrings: no documented ARKit face-mesh ear vertex indices were found; the Snap approach (pivot at hook contact, pick a named landmark, then UV-space offset) is the manual SOP to copy — in Unity place Empties on the ARKit `ARFaceGeometry.obj` template at the lobe and store them as `anchor_ear_left/right` in the per-category template prefab.
- Shoes: sole plane on Y=0, heel-to-toe along +Z (glTF forward) for the Unity contract (note WANNA uses +X and Snap/Lens Studio uses cm — conversion required if re-using those assets); left/right as separate meshes; mirror with Blender Mirror modifier across X then apply, and re-check normals (mirroring flips winding); ARKit `left_foot_joint` is the ankle (child of `left_leg_joint`, parent of toes), so the config needs an ankle→sole offset ≈ ankle height, which Apple's `hipToFootOffset` sample implicitly treats as the floor (so the foot joint sits near the floor/heel in the neutral skeleton — verify on device).
- Hat: origin at the inner crown contact point; vertical offset from the ARKit face anchor must be measured against the face template; add `anchor_head_top`.
- Furniture: bottom-centre origin, real dimensions from product spec (W×D×H in metres), front faces +Z; wall art: back-centre origin (on the wall plane), front faces +Z, store thickness in config so the wall offset is correct.

## KQ4. Garments manually: Mixamo, Marvelous Designer / CLO, Blender Rigify + weight transfer, mapping to Unity Humanoid and ARKit body joints, time per garment

### Takeaway
ARKit's own requirement is a 91-joint, exactly named, T-posed, +Z-forward skeleton with ≤4 influences per vertex and no retargeting; the practical manual route is to rig a base body (Mixamo free-but-unstable, Auto-Rig Pro $50, or Rigify free), transfer weights body→garment, and drive the rig from AR Foundation's `ARHumanBody` joints (directly if the rig uses ARKit names, or via Unity Humanoid retargeting otherwise). Marvelous Designer is the standard paid garment tool ($39/mo or $280/yr personal).

### Cited Findings
- ARKit motion capture requirements: model "must use a scene coordinate system that uses +Y for up, +Z for forward, and +X for right" and "face forward on the +Z axis"; skeleton "must exactly match ARKit's required joint names" and hierarchy (but "you don't have to bind vertices to every bone"); "rigged in a standard T-pose"; "No more than four joints should contribute to the movement of any single vertex"; torso = `hips_joint` (root child of `root`) + `spine_1_joint`…`spine_7_joint`; neck `neck_1_joint`…`neck_4_joint`, `head_joint`; arms `*_shoulder_1_joint → *_arm_joint → *_forearm_joint → *_hand_joint`; legs `*_upLeg_joint → *_leg_joint → *_foot_joint → *_toes_joint → *_toesEnd_joint`; full finger lists given. — [Apple: Validating a Model for Motion Capture](https://developer.apple.com/documentation/arkit/validating-a-model-for-motion-capture)
- Apple rigging workflow: download the "Biped-Robot.zip" (USDZ + FBX) and "rig it to the skeleton from the robot model"; "unbind and delete the robot mesh"; "There should be no geometry descending from joints, and no joints descending from geometry"; "the X axis still points down the length of the bone"; "The Motion Capture feature doesn't retarget motion … If your custom character's proportions differ substantially from the provided skeleton, the puppeteering functionality may not perform as expected"; export USDZ, or "export as a GLTF or USD file and then use Reality Converter". — [Apple: Rigging a Model for Motion Capture](https://developer.apple.com/documentation/arkit/rigging-a-model-for-motion-capture)
- Unity samples drive a 91-bone prefab by name from `ARHumanBody.joints[i].localPose` (see KQ2). — [BoneController.cs](https://github.com/Unity-Technologies/arfoundation-samples/blob/main/Assets/Scripts/Runtime/BoneController.cs)
- Mixamo (vendor guide, snippets): "still online and still free with an Adobe account, but it's in maintenance mode"; "authenticated features began failing in production on June 16, 2025" with login/upload/download errors persisting; "accepts only bipedal humanoid characters"; alternatives named: Reallusion AccuRIG, Cinevva browser auto-rigger, Quaternius animation library. — [Cinevva: Mixamo and alternatives (2026)](https://app.cinevva.com/guides/free-character-animations-rigging)

- Auto-Rig Pro (competitor blog, snippet; store page blocked): "$25 for the Lite version or $50 for the Full version"; Full "includes the core addon, the Smart tool for biped body recognition, FBX and GLTF exporters for Unreal and Unity, and the Remap tool for animation retargeting"; team licences "$162 for 10 seats and $227 for 20 seats". — [Sorceress blog on Auto-Rig Pro pricing](https://sorceress.games/blog/auto-rig-pro-free-download-the-honest-2026-path); creator page [artell on Superhive](https://superhivemarket.com/creators/artell)
- Marvelous Designer 2026 pricing (snippets): "Personal subscriptions cost $39/month or $280/year"; "Enterprise subscriptions cost $199/month or $2,000/year for Windows and macOS, or $2,300/year including Linux"; new indie tier "on request" for studios with "at least two employees, annual revenue below $500,000 USD, and legal registration". — [CGPress: MD indie pricing](https://cgpress.org/archives/marvelous-designer-introduces-indie-pricing.html); [Digital Production, Jan 2026](https://digitalproduction.com/2026/01/12/marvelous-designer-adds-indie-pricing-quietly/); MD 2026.1 released Aug 2026 — [CG Channel](https://www.cgchannel.com/2026/08/clo-virtual-fashion-releases-marvelous-designer-2026-1/)
- Snap Clothing Try-On: "Create a new garment 3D model in a 3D editor and configure imported models to track the user body" (snippet). — [Snap: Clothing Try-On](https://developers.snap.com/lens-studio/features/try-on/clothing-try-on)

### Inferences
- Manual garment SOP (free path): (1) import generator GLB (garment + mannequin); (2) separate garment from mannequin (Edit mode ▸ P ▸ By loose parts / by material), keep the mannequin as the weight donor; (3) rig the mannequin — Rigify human metarig (free) or Auto-Rig Pro "Smart" ($50) — or upload the nude mannequin to Mixamo if it is working that day; (4) parent garment to the armature with empty groups, then Data Transfer modifier (Vertex Groups, Nearest Face Interpolated) or Weights ▸ Transfer Weights from the mannequin, limit to 4 influences (Weights ▸ Limit Total) to satisfy ARKit's ≤4 rule; (5) delete the mannequin (or keep an invisible depth-only occluder copy — same idea as Snap's Face Occluder and Apple's occlusion geometry); (6) T-pose, +Z forward, metres; (7) export GLB with Skinning ON, "Export Deformation Bones Only" ON, "Use Rest Position Armature" ON, no animations; (8) in Unity, either (a) rename bones to ARKit names and drive with the samples' `BoneController` (no retargeting, best fidelity, matches Apple's "no retarget" model), or (b) import as Humanoid, create Avatar, Enforce T-Pose, and retarget from a Humanoid-configured ARKit skeleton via an Animator; (9) add cloth collider proxies if using Unity Cloth (optional).
- Marvelous Designer/CLO path: pattern the garment on an A/T-posed avatar sized to the ARKit robot proportions, simulate, export the garment as FBX/glTF with the avatar's skin weights ("Export with skin weights" in MD is prior knowledge — unverified here), then the same Unity step. MD's advantage over AI meshes is clean quads + UVs; its cost is $280/yr personal.
- Time per garment: using the vendor retopo numbers (1–4 h for characters) plus rigging/weight transfer/testing, expect roughly half a day to a full day per garment for a technical artist — this is an estimate, not a sourced figure.

- Rigify manual pages, Blender Data Transfer modifier docs, and Unity's current Humanoid-avatar page could not be fetched (hosts blocked / search budget exhausted).
- Mixamo's upload limits (polycount/file size/format) and current 2026 uptime were not obtainable from Adobe (helpx blocked); the status claims come from a vendor blog.
- Marvelous Designer export options (glTF/FBX with weights) and Auto-Rig Pro's official price page were not verifiable (vendor sites blocked).

## KQ5. Industry QA checklists (Khronos 3D Commerce, Shopify, Amazon, Wayfair, IKEA, Apple AR Quick Look, Snap try-on, Meta Spark) and a 5-minute reviewer checklist

### Takeaway
Across Khronos, Apple, Shopify, Amazon, Snap and WANNA the common numeric envelope for mobile AR product assets is ≤100 k triangles (65 k for shoes, 60 k for skinned meshes), ≤2048² textures (Amazon allows 4K), 5–15 MB file size, metres at 1:1, UVs in 0–1, PBR metal/rough, and a defined pivot/forward; the Khronos glTF Asset Auditor encodes most of these as default thresholds and can serve as the 5-minute review.

### Cited Findings
- Khronos Asset Creation Guidelines 2.0 (Aug 2025, CC BY 4.0; v1 Oct 2020): 1 unit = 1 m; 1:1 scale; bottom-centre pivot; glTF is "triangles only"; "all of the UV coordinates should be between 0 and 1" for non-tiling content; island margins to avoid bleed; multiple UV maps "not recommended" (USDZ support); Metallic-Roughness workflow, metallic "either white (metal) or black (non-metal)"; textures png/jpg/webp/ktx2, author lossless PNG then derive; file names a–z, 0–9, `_`/`-`, start with a letter; `alphaMode` Mask vs Blend; remove unused animation; "Models should only have as much geometry as necessary" — no hard triangle cap. — [Khronos 3DC Guidelines v2](https://github.com/KhronosGroup/3DC-Asset-Creation/blob/main/asset-creation-guidelines/RealtimeAssetCreationGuidelines.md); repo — [KhronosGroup/3DC-Asset-Creation](https://github.com/KhronosGroup/3DC-Asset-Creation); announcement — [Khronos blog, SIGGRAPH 2025](https://www.khronos.org/blog/introducing-asset-creation-guidelines-2.0-siggraph-2025)
- Khronos 3D Commerce Viewer Certification: viewers render a set of test glTFs and submit images for review "within 30 days"; certified viewers listed in a public registry (snippet). — [Khronos 3D Commerce certification](https://www.khronos.org/3dcommerce/certification/)
- Khronos glTF Asset Auditor (3DC-Validator) default thresholds: "maximum 100,000 triangles, 5 materials maximum, texture heights between 512-2048 pixels"; checks include file size, triangle/material/node/mesh/primitive counts, "Clean origin for root node", beveled edges (no hard edges ≥90°), non-manifold edges, model dimensions with tolerance, power-of-two/square textures, PBR colour range (30–243 luminosity), UV 0–1, inverted/overlapping UVs, gutter width, texel density; CLI (Node), web UI, TypeScript library; "Files with Draco mesh compression are unsupported". — [KhronosGroup/3DC-Validator](https://github.com/KhronosGroup/3DC-Validator); web — [khronos.org/gltf/gltf-asset-auditor](https://www.khronos.org/gltf/gltf-asset-auditor/)
- Apple AR Quick Look (Apple engineer on dev forums, Nov 2021, citing WWDC 2018): "100K polygons", "One set of 2048x2048 textures", "10 seconds of animations" for compatibility down to iPhone 7; RealityKit downsamples textures on low-memory devices. — [Apple Developer Forums thread 693867](https://developer.apple.com/forums/thread/693867)
- Community/vendor summaries of Quick Look: files "under 10 MB is considered safe", "too large to open" errors depend on in-memory texture size, not file size (snippets). — [Tripo3D USDZ guide](https://www.tripo3d.ai/blog/explore/usdz-requirements-for-ios-quick-look-previews); [Needle forum](https://forum.needle.tools/t/file-size-limit-in-ios-quicklook/2115)
- Shopify (snippet): file size "generally … less than 15 MB"; "only as much geometry as necessary"; GLB textures = diffuse, normal, "a single map with occlusion/roughness/metalness mapped to red/green/blue channels", optional emissive; optimized JPG preferred; real-world scale in metres; deliver GLB. — [Shopify 3D model standards checklist](https://help.shopify.com/partners/resources/creating-3d-models/3d-model-standards-checklist); [Shopify blog](https://www.shopify.com.au/blog/3d-models-video)
- Amazon (vendor blog summaries, snippets): "up to 200,000 triangles", "maximum 5MB file size", PBR textures "2K to 4K", PNG/JPEG embedded in GLB, single atlas with UVs in 0–1. — [Neural4D Amazon GLB guide 2026](https://blog.neural4d.com/image-to-3d/3d-product-rendering-for-ecommerce-amazon-glb-guide-2026/); [Maverick Frame: Amazon/Wayfair/Shopify requirements](https://www.maverickframe.com/blog/3d-model-requirements-amazon-wayfair-shopify/)
- WANNA (shoes): 65 k tris/shoe, 105 primitives, 2048² textures, 18,873,368 total texture px, 50 MB archive, one UV set, toe → +X, L/R separate (snippets). — [WANNA shoes](https://wanna.helpjuice.com/shoes-category/shoes-3d-models)
- Snap Lens Studio general (snippet; exact page URL not captured): keep models "under 100,000 triangles, or 60,000 triangles for meshes with joints/skinning"; name meshes/bones descriptively; merge meshes; place pivot sensibly; correct normals; UV map + texture required; use normal maps for detail. — [Snap asset library publishing guide (nearest captured URL)](https://developers.snap.com/lens-studio/assets-pipeline/asset-library/asset-library-publishing-guide)

### Inferences
- 5-minute reviewer checklist (each item maps to a sourced rule above): (1) `gltf_validator file.glb -o` → zero errors; (2) `gltf-transform inspect file.glb` → triangles ≤100 k (≤65 k shoes, ≤60 k skinned), draw calls/primitives small, textures ≤2048² and power-of-two, file ≤10–15 MB; (3) bounding box from `inspect` matches spec dimensions ±2 %; (4) root node at origin, pivot at contract point (bottom-centre / back-centre / contact point); (5) front faces +Z in a glTF viewer; (6) anchor nodes present with contract names and `extras` populated; (7) single UV set, UVs in 0–1, no inverted islands (Asset Auditor); (8) materials metal/rough, metallic binary, normal maps tangent-space; (9) no stray animations/skins unless rigged; (10) Draco OFF for assets that will go through the Asset Auditor or an importer without Draco support.
- Running the Khronos Asset Auditor with a per-category JSON schema (dimensions, max triangles, texture range) is the closest existing "AR asset linter"; no open-source AR-specific linter beyond it and glTF-Transform was found.

### Gaps
- Wayfair and IKEA model requirements were not reachable (only a secondary blog that could not be fetched).
- Snap's official try-on asset-prep pages and Meta Spark archives (Spark is sunset) were blocked; no Meta Spark numbers captured.

## KQ6. Validation tools: glTF Validator, glTF-Transform, 3D-Print Toolbox, MeshLab, trimesh, UnityGLTF warnings, Unity mesh stats, "AR asset linting" projects

### Takeaway
A free CLI validation stack exists today: Khronos glTF Validator (spec conformance), glTF-Transform `inspect`/`validate`/`center`/`prune`/`dedup`/`weld`/`simplify`/`resize` (stats + fixes), Khronos glTF Asset Auditor (commerce thresholds), Blender 3D-Print Toolbox (manifold/degenerate/thickness) and trimesh (scriptable watertight/bounds/node-graph checks).

### Cited Findings
- glTF Validator CLI: `gltf_validator [<options>] <input>`; report written to `<asset_filename>.report.json`; options `-o/--stdout`, `-r/--validate-resources` (default on), `-a/--all` (show warnings), `-m/--messages`, `-c/--config` (YAML), `-h/--threads` for directory batches; web drag-and-drop at github.khronos.org/glTF-Validator; npm package `gltf-validator`; NuGet `GltfValidator`. — [glTF-Validator README](https://raw.githubusercontent.com/KhronosGroup/glTF-Validator/main/README.md)

- 3D-Print Toolbox checks (manifold, intersections, degenerate, distorted, thickness, sharp edges, overhang; Make Manifold; scale-to-bounds). — [object_print3d_utils](https://raw.githubusercontent.com/blender/blender-addons/main/object_print3d_utils/__init__.py)
- trimesh checks (`is_watertight`, `euler_number`, `bounds`, `fix_normals`, `fill_holes`, `split`, `scene.graph`, glTF/GLB I/O). — [mikedh/trimesh](https://github.com/mikedh/trimesh)
- glTFast shows "import settings and eventual warnings/errors in the Inspector" for an imported glTF (snippet). — [glTFast ImportEditor](https://docs.unity3d.com/Packages/com.unity.cloud.gltfast@6.2/manual/ImportEditor.html)
- Vulkan tutorial section documents the Khronos validator as the reference tool in a production pipeline (snippet). — [Vulkan docs: glTF validation](https://docs.vulkan.org/tutorial/latest/Advanced_gltf/Tooling_Production_Pipeline/03_validation.html)

### Inferences
- A one-file bash "lint" for reviewers: `gltf_validator -o -a asset.glb && gltf-transform inspect asset.glb --format md && node 3dc-validator --schema category.json asset.glb`; plus a 10-line trimesh script that loads the GLB, asserts `extents` within spec ±2 %, asserts `scene.graph` contains the contract anchor node names, and asserts `is_watertight` per mesh (warn only, since jewellery often is not).
- Keep Draco off until the last step because the Asset Auditor cannot read Draco files and UnityGLTF import of Draco needs an extra package (unverified).

### Gaps
- MeshLab filter names (close holes, non-manifold cleanup) and UnityGLTF's specific import warnings were not sourced (no fetchable page / search budget).
- No open-source project explicitly branded "AR asset linting" was found beyond the Khronos Asset Auditor.
