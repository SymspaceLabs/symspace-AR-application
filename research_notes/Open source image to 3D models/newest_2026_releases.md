# Newest open-source 3D asset generation releases, Jan–Oct 2026 (with late-2025 context)

Research date: 2026-10-07. Method: web search + direct fetch of GitHub READMEs / licence files where reachable. Several key pages (huggingface.co, arxiv.org, zhuanlan.zhihu.com, blog.comfy.org, app.cinevva.com, triposr.org, comfyui-wiki.com) were blocked by the network proxy, so some facts rest on GitHub READMEs and secondary coverage; these cases are flagged.

**Headline for the report writer:** the open-weight "frontier" moved twice since the typical 2025 reports: (1) **Microsoft TRELLIS.2** (16 Dec 2025, MIT, 4B params, O-Voxel, up to 1536³, PBR) and (2) **TencentARC Pixal3D** (May 2026, MIT, SIGGRAPH 2026, built on TRELLIS.2 + Direct3D-S2, pixel-aligned back-projection, PBR GLB, multi-view inference added Sep 2026). Tencent's object-asset line **did not** open-source anything after Hunyuan3D-2.1 / Omni / Part (June–Sep 2025): 2.5, PolyGen, 3.0 and 3.1 remain hosted-only. Tencent's 2026 open releases were in *world/scene* generation (HY-World 2.0, Apr–May 2026). VAST/Tripo's flagship P1.0/H3.1/P2.0 (2026) are closed; its 2026 open releases are TripoSplat (Gaussians), SkinTokens (rigging) and scene-level work. Meta SAM 3D Objects (19 Nov 2025, SAM License) is open and got encoder weights + a leaderboard in June 2026. Roblox CubePart (May 2026) is open but research-only.

## Key Question 1: What new open-weight image-to-3D / text-to-3D / multimodal-to-3D models were released in 2026 (plus under-covered late-2025)?

### Takeaway
Only two new *object-asset* open-weight foundation models of frontier quality appeared in the window: TRELLIS.2 (Dec 2025) and Pixal3D (May 2026, built on TRELLIS.2). Everything else in 2026 is either closed (Hunyuan3D 3.x, Tripo P1.0/H3.1/P2.0, Meshy 7, Seed3D), research-only licensed (Roblox CubePart, NVIDIA PartPacker), or targets a different output (Gaussians, scenes/worlds, rigs, parts).

### Inferences
- For an *object-asset, image-to-3D* report, the ranking of open candidates is: Pixal3D (newest, MIT, builds on and claims to improve TRELLIS.2 fidelity via pixel alignment, multi-view support) ≥ TRELLIS.2 (MIT, most ecosystem support) > Hunyuan3D-2.1 (+Omni/Part) (older, restrictive licence, but strongest open texture/PBR paint stack per community) > SAM 3D Objects (strong on in-the-wild photos with occlusion, outputs Gaussians/mesh, SAM License) > TripoSG/TripoSF (2025, MIT, geometry-only).
- Because Pixal3D is built on TRELLIS.2 + Direct3D-S2, both MIT, the entire stack is commercially usable without territory/MAU clauses — unlike Hunyuan3D.
- Tencent appears to have shifted its open-source effort from object assets (Hunyuan3D) to world models (HY-World 2.0/2.1) while monetising 3D 3.x; a report should not describe "Hunyuan3D 3.0" as open.

## Key Question 2: Native / autoregressive artist-topology mesh generation — what is new and is it practical for low-poly AR/game assets?

### Takeaway
2026 produced a wave of papers (MeshRipple, QuadGPT, QuadLink, Mesh-Pro, MeshFIM, Nexus, a Meshy "T2" paper) pushing toward quad-dominant and larger meshes, but only MeshRipple (and the 2025 open set: MeshAnything v1/v2, DeepMesh, PartCrafter) has public code + weights; the strongest quad-native systems (Tripo P2.0, Hunyuan3D-PolyGen) are closed.

### Cited Findings
- **MeshRipple** (CVPR 2026 Highlight; arXiv 2512.07514): "topology-aligned autoregressive framework" with frontier-aware BFS tokenization, expansive prediction, sparse-attention global memory; **code released**, pretrained weights on Google Drive: `meshRipple_10k.pth` (10k faces, full attention) and `meshRipple_nsa.pth` (20k faces, NSA); training code "TODO"; licence not specified in README. — [MeshRipple GitHub](https://github.com/MayMhappy/MeshRipple); [project page](https://maymhappy.github.io/MeshRipple/index.html)
- **QuadGPT** (ICLR 2026; HKUST + Tencent Hunyuan): "first autoregressive framework that directly generates native quadrilateral and mixed-element meshes", with tDPO RL fine-tuning; paper says a public API/online interface will be provided; **no GitHub code/weights found**. — [ICLR 2026 proceedings](https://proceedings.iclr.cc/paper_files/paper/2026/hash/255a6f2248df64fbd37267cf93a25b7c-Abstract-Conference.html); [project page](https://hitcslj.github.io/QuadGPT/); [arXiv 2509.21420](https://arxiv.org/abs/2509.21420v2)
- **Mesh-Pro** (arXiv 2603.00526, Mar 2026): RL preference optimisation for artist-style quad meshes; code status unknown. — [arXiv](https://arxiv.org/pdf/2603.00526)
- **QuadLink** (arXiv 2605.16813, May 2026): autoregressive quad-dominant mesh generation via point-relation learning; code status unknown. — [arXiv](https://arxiv.org/pdf/2605.16813)
- **MeshFIM** (arXiv 2605.08744, May 2026): local low-poly mesh *editing* via fill-in-the-middle autoregressive generation; code status unknown. — [arXiv](https://arxiv.org/pdf/2605.08744)
- **Nexus: Native Mesh Generation with Diffusion** (arXiv 2607.13563, Jul 2026; ACM TOG doi 10.1145/3811344): replaces serialization with diffusion — hierarchical vertex generation then vertex-conditioned topology generation; code status unknown. — [arXiv](https://arxiv.org/abs/2607.13563); [ACM](https://dl.acm.org/doi/10.1145/3811344)
- **Meshy "T2"** paper (arXiv 2607.28675, Jul 2026): "generates compact meshes at interactive speed, with controllable face budgets and explicit connectivity … vertices and edges are generated jointly"; weights not released (Meshy models are closed). — [arXiv html](https://arxiv.org/html/2607.28675)
- **Tripo P2.0** (21 Sep 2026, closed) claims first native quad-mesh generation — see KQ1. — [pasqualepillitteri.it](https://pasqualepillitteri.it/en/news/17686/tripo-ai-p2-funding-quad-topology)
- **Hunyuan3D-PolyGen** (8 Jul 2025): "production-ready 3D assets with clean quad/tri meshes, reducing creation time by 70% and boosting topology neatness by 35%" — **hosted only, no weights** (issue #111 unanswered). — [Issue #111](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/issues/111)
- 2025 open baselines still current: MeshAnything (ICLR 2025) and DeepMesh (ICCV 2025, RL) have official code; EdgeRunner (ICLR 2025), TreeMeshGPT, FastMesh, BPT listed in the mesh-generation topic. — [MeshAnything](https://buaacyw.github.io/mesh-anything/); [GitHub topic mesh-generation](https://github.com/topics/mesh-generation)
- NVIDIA Meshtron (up to 64k faces, 1024-level coordinates) remains paper-only. — [arXiv 2412.09548](https://arxiv.org/html/2412.09548v1)

### Inferences
- For low-poly AR assets, the practical open route in Oct 2026 is still: dense mesh from TRELLIS.2/Pixal3D → decimation/retopology, optionally MeshRipple (≤20k faces) or MeshAnything-V2/DeepMesh as a retopology-style step. Native quad generation is a closed-product advantage (Tripo P2.0, PolyGen).
- MeshRipple's unspecified licence is a risk for commercial use; verify before adopting.

### Gaps
- Could not confirm code availability for QuadGPT, QuadLink, Mesh-Pro, MeshFIM, Nexus (arXiv pages blocked; no repos surfaced in search).
- No benchmark comparing MeshRipple vs DeepMesh vs BPT on low-poly game assets found.

## Key Question 3: Rigging / animation and part-level generation — status in 2026

### Takeaway
Rigging and parts saw more genuine open-weight progress in 2026 than core image-to-3D: VAST SkinTokens (MIT, unifies skeleton + skinning), UniMate (text-to-motion for any skeleton, code MIT / weights CC-BY-NC), Roblox CubePart (research-only), plus a cluster of part-generation papers (X-Part, FullPart, UniPart, DreamPartGen, KaiNinja, SAM3D-Part, PhysX-Omni) whose code status is mostly unverified.

### Cited Findings
- **UniRig** (VAST + Tsinghua, SIGGRAPH 2025): autoregressive skeleton generation with DFS skeleton-tree tokenization; open-sourced April 2025. — [UniRig GitHub](https://github.com/VAST-AI-Research/UniRig); [ComfyUI-Wiki, 12 Apr 2025](https://comfyui-wiki.com/en/news/2025-04-12-unirig-one-model-to-rig-them-all)
- **SkinTokens** (VAST, arXiv 2602.04805, Feb 2026): "successor to UniRig"; unifies skeleton and skinning into one autoregressive sequence via learned discrete skin tokens (FSQ-CVAE tokenizer + TokenRig AR model); claims "98%–133% improvement in skinning accuracy" and "17%–22% improvement in bone prediction"; **weights on HF, MIT licence**. — [SkinTokens GitHub](https://github.com/VAST-AI-Research/SkinTokens)
- **UniMate** (SIGGRAPH Asia 2026): unified diffusion model generating motion for bipedal/quadrupedal/avian/marine/insectoid/serpentine/rigid skeletons from text; timeline: demo 1 Aug 2026, UniML3D dataset 30 Aug, code 6 Sep, preview checkpoints 27 Sep, "bring your own rig" tools 5 Oct 2026; **code MIT, checkpoints CC BY-NC 4.0**. — [UniMate GitHub](https://github.com/Friedrich-M/UniMate)
- Other 2026 rigging papers (code status unverified): ViP-Rig (visual-prompted controllable rigging, arXiv 2607.27982); "Branch-Centric Tokenization and Test-Time Augmentation for Skeleton Generation" (arXiv 2609.06218). — [ViP-Rig](https://arxiv.org/pdf/2607.27982); [arXiv 2609.06218](https://arxiv.org/pdf/2609.06218)
- **Hunyuan3D-Part (P3-SAM + X-Part)**, 28 Sep 2025, open (light X-Part); full X-Part only in Hunyuan3D-Studio. — [GitHub](https://github.com/Tencent-Hunyuan/Hunyuan3D-Part)
- **PartCrafter** (NeurIPS 2025) fully open; **OmniPart** (SIGGRAPH Asia 2025); **UniPart** (arXiv 2512.09435); **PartPacker** (NVIDIA, open weights, non-commercial licence). — [PartCrafter](https://github.com/wgsxm/PartCrafter); [OmniPart](https://arxiv.org/pdf/2507.06165); [UniPart](https://arxiv.org/pdf/2512.09435); [PartPacker HF](https://huggingface.co/nvidia/PartPacker)

## Key Question 4: Research trends in 2026 (representations, resolution, PBR, VAEs, speed, multi-view, world/scene generation)

### Takeaway
The field consolidated on sparse-voxel structured latents (TRELLIS-style) at 1024³–1536³ with native PBR, and 2026's main innovation was conditioning (pixel-aligned back-projection, multi-view, box/pose/point controls) rather than a new base representation; world/scene generation (HY-World 2.0, StereoWorld, Mira-Scene, Apple SHARP) became the most active open area, but it targets 3DGS/scene outputs rather than AR-ready object meshes.

### Cited Findings
- **Sparse structured latents + O-Voxel**: TRELLIS.2's O-Voxel is "a field-free sparse voxel structure" handling open surfaces and complex topology; Sparse 3D VAE with 16× downsampling; ~9.6K tokens for a 1024³ textured asset. — [TRELLIS.2 GitHub](https://github.com/microsoft/TRELLIS.2); [arXiv 2512.14692](https://arxiv.org/html/2512.14692v1)
- **High-res VAEs (2025 base)**: Sparc3D (Sparcubes + Sparconv-VAE, 1024³, arXiv 2505.14521); Direct3D-S2 (Spatial Sparse Attention, MIT, 26 May 2025, Nanjing U/DreamTech/Fudan/Oxford); Ultra3D (sparse voxel res 128 → 1024 output, part attention, arXiv 2507.17745). Sparc3D is now described as Hitem3D's proprietary model (up to "1536³ Pro"). — [Sparc3D](https://arxiv.org/html/2505.14521v2); [Direct3D-S2](https://arxiv.org/pdf/2505.17412); [hyper.ai on Direct3D-S2](https://hyper.ai/en/notebooks/40982); [Ultra3D](https://arxiv.org/html/2507.17745v1); [Hitem3D/Sparc3D](https://www.producthunt.com/products/hitem3d-2-0/launches/hitem3d)
- **Pixel-aligned conditioning**: Pixal3D "explicitly lifts pixel features into 3D through back-projection, establishing direct pixel-to-3D correspondences" for "near-reconstruction-level fidelity". — [Pixal3D GitHub](https://github.com/TencentARC/Pixal3D)
- **Multi-view conditioning**: Pixal3D multi-view inference (Sep 2026); community TRELLIS.2 ComfyUI wrapper supports up to 16 views (default 4) with low-VRAM mode; Hunyuan 3D 3.1 (hosted) accepts 8 views. — [deepwiki ComfyUI-Trellis2 multi-view](https://deepwiki.com/visualbruno/ComfyUI-Trellis2/3.3.5-multi-view-3d-generation); [Xipong AMD/MultiView fork](https://github.com/Xipong/ComfyUI-Trellis2-AMD-3DMultiView); [toolnavs on 3.1](https://toolnavs.com/de/article/1123-tencent-hy-3d-31-is-launched-on-the-global-platform-and-supports-8-view-input)
- **Speed / distillation**: SAM 3D paper reports distillation to 1-step giving ~38× inference speed-up vs 25-step flow matching. TRELLIS.2 ~3 s at 512³ on H100. No dedicated 2026 open one-step image-to-3D model found. — [SAM 3D arXiv 2511.16624](https://arxiv.org/pdf/2511.16624); [TRELLIS.2](https://github.com/microsoft/TRELLIS.2)
- **Low-VRAM democratisation**: GGUF-quantised TRELLIS.2 runs on 6 GB VRAM via a ComfyUI fork; Q4/Q5 workflows at 512 res on 8 GB cards; visualbruno/ComfyUI-Trellis2 is the maintained wrapper. — [DailyTopAI GGUF guide](https://dailytopai.com/article/how-to-run-trellis-2-3d-ai-locally-on-just-6gb-vram-with-gguf-44.html); [trellis2.app low-VRAM](https://trellis2.app/blog/trellis-2-low-vram)
- **Multi-condition control**: Hunyuan3D-Omni (bbox, pose, point cloud, voxel), Cube 3D v0.5 (bounding box), CubePart (parts schema). — [Omni](https://github.com/Tencent-Hunyuan/Hunyuan3D-Omni); [Roblox/cube](https://github.com/Roblox/cube/)
- **World / scene generation**: HY-World 2.0 (Apr–May 2026, open) outputs 3DGS + meshes from text/image/multi-view/video; VAST StereoWorld (CVPR 2026) and Mira-Scene (MIT) updated Sep 2026; Apple SHARP (single photo → scene in <1 s) and Apple Matrix3D (2–3 images → scenes/objects, code on GitHub); MIDI-3D (VAST, CVPR 2025) single image → multi-instance scene. — [HY-World-2.0](https://github.com/Tencent-Hunyuan/HY-World-2.0); [VAST org](https://github.com/VAST-AI-Research); [Matrix3D coverage](https://www.cdomagazine.tech/aiml/apple-unveils-matrix3d-new-ai-model-reconstructs-3d-scenes-from-photos)
- **Simulation-ready assets**: Seed3D 1.0 (closed) and PhysX-Omni (paper) explicitly target simulation-ready outputs. — [Seed3D](https://arxiv.org/html/2510.19944v1); [PhysX-Omni](https://arxiv.org/pdf/2605.21572)

### Inferences
- Scene/world generation matters for AR only for environment reconstruction or virtual backdrops; for placing individual objects in a real room, object-level models (Pixal3D/TRELLIS.2/SAM 3D Objects) remain the relevant class. SAM 3D Objects is notable for predicting object *pose/layout* from cluttered photos, which is closer to an AR capture workflow.
- The direction of travel (1024³+ resolution, PBR, pixel alignment) increases output fidelity but also polygon counts; AR pipelines need a decimation/LOD stage regardless.

### Gaps
- No 2026 open "one-step" image-to-3D distillation release located.
- Could not verify Apple SHARP/Matrix3D licences or exact dates.

## Key Question 5: What practitioners consider the default open stack in 2026, and surprises (relicensing, abandonment, removed weights)

### Takeaway
Community and comparison sites converge on TRELLIS.2 as the 2026 default (MIT, PBR, best ecosystem, ComfyUI-native), with Pixal3D as the newer MIT challenger built on it and Hunyuan3D-2.1 kept mainly for its PBR paint/texturing stage; the main "surprise" is that Tencent stopped open-sourcing Hunyuan3D after 2.1 (issue threads unanswered for >1 year) while StepFun's Step1X-3D went dormant.

### Cited Findings
- "TRELLIS 2 is currently the quality leader among fully open models … the only frontier-quality model whose licence has no territory, revenue or user-count clause." — [Cinevva comparison](https://app.cinevva.com/guides/ai-3d-model-generators) (secondary; page itself blocked, quoted from search snippet)
- Head-to-head summary: "the PBR paint model is still the strongest open texturing stack for Hunyuan3D 2.1"; Hunyuan3D 2.1 needs 10 GB geometry / 29 GB with texture vs TRELLIS.2 24 GB minimum. — [triposr.org Hunyuan3D vs TRELLIS.2](https://triposr.org/blog/hunyuan3d-vs-trellis) (secondary); VRAM confirmed by [Hunyuan3D-2.1 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1) and [TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2)
- **Hunyuan3D 2.1 licence (primary text)**: "Tencent Hunyuan 3D 2.1 Community License Agreement"; Territory = "worldwide territory, excluding the territory of the European Union, United Kingdom and South Korea"; if MAU "greater than 1 million monthly active users in the preceding calendar month, You must request a license from Tencent"; outputs may not be used "to improve any other AI model"; generated content must be labelled as machine-generated. — [LICENSE](https://raw.githubusercontent.com/Tencent-Hunyuan/Hunyuan3D-2.1/main/LICENSE)
- ComfyUI now ships native Trellis.2 and Pixal3D support (blog post title); maintained community wrapper visualbruno/ComfyUI-Trellis2 plus AMD/ROCm fork. — [ComfyUI blog](https://blog.comfy.org/p/trellis2-and-pixal3d-are-now-native); [Xipong fork](https://github.com/Xipong/ComfyUI-Trellis2-AMD-3DMultiView)
- Pixal3D has an Apple-Silicon community port and Godot-oriented GLB workflow. — [Pixal3D-mac](https://github.com/pawel-mazurkiewicz/Pixal3D-mac); [Godot forum](https://forum.godotengine.org/t/pixal3d-open-source-image-to-3d-generation-with-glb-export-for-godot/143058)

  - Tencent: no object-asset open release since Sep 2025; 2.5/PolyGen/3.0/3.1 hosted-only; issue #111 open since 17 Jul 2025 with no reply. — [Issue #111](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/issues/111)

### Inferences
- A 2026 report should present the default open stack as: **Pixal3D or TRELLIS.2 (MIT) for geometry + PBR → optional Hunyuan3D-2.1 Paint for texture (licence permitting) → SkinTokens (MIT) for rigging → MeshRipple/MeshAnything-V2/decimation for low-poly**, with SAM 3D Objects as the choice for cluttered real-world photos.
- Any report that lists Hunyuan3D 2.x as "latest Tencent" is not stale on open weights, but is stale if it omits TRELLIS.2 and Pixal3D or treats Hunyuan3D 3.0 as open.
