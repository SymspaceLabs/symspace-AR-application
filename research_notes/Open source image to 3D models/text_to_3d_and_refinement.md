# Open-source text-to-3D and text-guided refinement of image-to-3D outputs (as of 2026-10-07)

Scope note: this covers (a) open-weight text-to-3D models and (b) ways to use a text prompt to improve or edit a 3D asset that was first produced by an image-to-3D model. Image-to-3D model selection itself is covered by other researchers. Network constraints during this research: arxiv.org, huggingface.co, alphaxiv.org, openaccess.thecvf.com, and most GitHub Pages project sites were blocked by the egress proxy, so paper details below come from GitHub READMEs, search-result abstracts, and secondary write-ups; where only a search snippet was available I say so.

Research date: 2026-10-07. End-user context: Unity mobile AR app; outputs ultimately need to be GLB/USDZ meshes with UV textures.

## Key Question 1: Which open-weight text-to-3D models exist and how good are they?

### Takeaway
Direct (native) text-to-3D open models exist (TRELLIS-text-base/large/xlarge, Roblox Cube 3D, legacy Point-E/Shap-E), but every major open lab, including Microsoft itself, states that the text-conditioned models are weaker than the image-conditioned ones and recommends text -> image -> image-to-3D instead. The 2025-2026 flagship open releases (TRELLIS.2, Hunyuan3D-2.1, Step1X-3D) are image-conditioned only.

### Cited Findings
- TRELLIS (Microsoft) ships four pretrained models: TRELLIS-image-large (1.2B, image-to-3D), TRELLIS-text-base (342M), TRELLIS-text-large (1.1B), TRELLIS-text-xlarge (2.0B); text-to-3D models were released 03/25/2025 together with "variant generation" features; MIT license (submodules diffoctreerast and modified FlexiCubes have separate licenses); requires an NVIDIA GPU with at least 16 GB memory. The README states verbatim: "It is always recommended to use the image conditioned version of the models for better performance" and "Text-conditioned models are less creative and detailed due to data limitations." — [microsoft/TRELLIS README](https://github.com/microsoft/TRELLIS)
- The TRELLIS-text-xlarge model card (4.13 GB, MIT, arXiv 2412.01506) repeats: "It is always recommended to do text to 3D generation by first generating images using text-to-image models and then using TRELLIS-image models for 3D generation, as text-conditioned models are less creative and detailed due to data limitations." (snippet from search; huggingface.co itself was blocked) — [microsoft/TRELLIS-text-xlarge on Hugging Face](https://huggingface.co/microsoft/TRELLIS-text-xlarge/tree/main)
- TRELLIS.2 (Microsoft, 4B params, "TRELLIS.2-4B") is image-to-3D only: the README describes single-image input plus "shape-conditioned texture generation"; it outputs "Base Color, Roughness, Metallic, and Opacity" and an "extracted PBR-ready 3D asset in GLB format"; runtimes on an H100: 512^3 ~3 s (2 s shape + 1 s material), 1024^3 ~17 s, 1536^3 ~60 s; "An NVIDIA GPU with at least 24GB of memory is necessary"; MIT license (nvdiffrast / nvdiffrec dependencies under separate terms); no text prompt capability is mentioned. — [microsoft/TRELLIS.2 README](https://github.com/microsoft/TRELLIS.2) and [raw README](https://raw.githubusercontent.com/microsoft/TRELLIS.2/main/README.md)
- TRELLIS.2 was announced publicly on 2025-12-18 (ComfyUI-Wiki news item) as "a large 3D generative model with 4 billion parameters ... designed for high-fidelity image-to-3D"; a vendor comparison site gives 2025-12-16 as the release date. — [ComfyUI-Wiki news 2025-12-18](https://comfyui-wiki.com/news/2025-12-18-microsoft-trellis2-3d-generation); [3D AI Studio blog](https://www.3daistudio.com/blog/best-free-ai-3d-model-generators-2026)
- Hunyuan3D-2.0's text-to-3D path is a two-stage pipeline inside the Gradio app: `--enable_t23d` loads `HunyuanDiTPipeline('Tencent-Hunyuan/HunyuanDiT-v1.1-Diffusers-Distilled')`, calls `image = t2i_worker(caption)`, then runs the ordinary image-to-3D (background removal + shape + paint). It is off by default. — [Hunyuan3D-2 gradio_app.py](https://raw.githubusercontent.com/Tencent-Hunyuan/Hunyuan3D-2/main/gradio_app.py)
- Hunyuan3D-2 model family and release dates: Hunyuan3D-DiT-v2-0 (1.1B) and Hunyuan3D-Paint-v2-0 (1.3B) on 2025-01-21; Hunyuan3D-2mini (0.6B) and Hunyuan3D-2mv (1.1B, multi-view) on 2025-03-18; Hunyuan3D-DiT-v2-0-Turbo on 2025-03-19; Hunyuan3D-DiT-v2-1 (3.0B) on 2025-06-13. "It takes 6 GB VRAM for shape generation and 16 GB for shape and texture generation in total" (2.0). — [Tencent-Hunyuan/Hunyuan3D-2 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)
- Hunyuan3D-2.1 (released 2025-06-13 per GitHub; a ComfyUI-Wiki page says 2025-06-14) consists of Hunyuan3D-Shape-v2-1 (3.3B) and Hunyuan3D-Paint-v2-1 (2B, PBR). "It takes 10 GB VRAM for shape generation, 21GB for texture generation and 29GB for shape and texture generation in total." The 2.1 README documents image input only; no text prompt path is documented. — [Tencent-Hunyuan/Hunyuan3D-2.1 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1); [ComfyUI-Wiki Hunyuan3D 2.1](https://comfyui-wiki.com/en/models/hunyuan3d/hunyuan-3d-2-1)
- Hunyuan3D-2.1 license: "Tencent Hunyuan 3D 2.1 Community License Agreement"; it "DOES NOT APPLY IN THE EUROPEAN UNION, UNITED KINGDOM AND SOUTH KOREA" (Territory = worldwide excluding EU, UK, South Korea); a separate license must be requested if "the monthly active users of all products or services made available by or for Licensee is greater than 1 million monthly active users in the preceding calendar month", which "Tencent may grant to You in its sole discretion"; and "You must not use the Tencent Hunyuan 3D 2.1 Works or any Output or results ... to improve any other AI model". — [Hunyuan3D-2.1 LICENSE](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1/blob/main/LICENSE)
- Step1X-3D (StepFun, released 2025-05-13, Apache-2.0) is single-image input only; geometry via a "hybrid VAE-DiT" producing watertight TSDF, texture via an SD-XL-based module with "geometric conditioning and latent-space synchronization"; it "uniquely bridges 2D and 3D generation paradigms by supporting direct transfer of 2D control techniques (e.g., LoRA)"; geometry + texture needs 27-29 GB VRAM and ~152 s for 50 steps; outputs .glb. — [stepfun-ai/Step1X-3D README](https://github.com/stepfun-ai/Step1X-3D)
- Roblox Cube 3D is "a shape tokenizer and a text-to-shape generation model"; outputs are .obj meshes (no textures; "Texture generation" and "Scene layout generation" are listed as planned); latest is Cube 3D v0.5 (July 2025) which added "higher fidelity compositions and bounding box conditioning, trained on an additional ~2.8 million synthetic 3D assets"; recommends 24 GB VRAM with `--fast-inference`, 16 GB otherwise; runs on L40S/H100/A100 and Apple Silicon M2-4. License is a repository LICENSE file whose type was not visible in the fetched README; GitHub metadata labels it "other" and a Hugging Face mirror labels it "openrail" (search snippet, unverified). — [Roblox/cube README](https://github.com/Roblox/cube); [search snippet on license](https://awesome.ecosyste.ms/projects/github.com%2FRoblox%2Fcube); [Roblox announcement 2025-03](https://about.roblox.com/newsroom/2025/03/introducing-roblox-cube)
- Point-E (OpenAI, MIT) is still described in a 2026 round-up as "the most user-friendly text-to-3D model" but it is a legacy point-cloud model; the same round-up calls TRELLIS 2 "the quality leader among fully open models" and says Hunyuan3D 2.1 "offers best textural and material accuracy of any open model, with all weights and training code included" (vendor/blog opinion). — [CMARIX blog, 2026](https://www.cmarix.com/blog/top-open-source-ai-models-for-3d-image-generation/)
- Hunyuan 3D 3.0 (text, image, sketch and multi-view input, 1536^3 geometric resolution) is available in ComfyUI only through "Partner nodes" that call Tencent's API ("ComfyUI has natively integrated the corresponding Hunyuan 3D API"); I found no open weights for Hunyuan3D 2.5 or 3.0. — [ComfyUI docs: Hunyuan3D 3.0 partner nodes](https://docs.comfy.org/tutorials/partner-nodes/hunyuan3d/hunyuan3d-3-0)
- Arko-T (arXiv 2606.30429, June 2026) is a "foundation model for text-to-structured 3D generation" that outputs parametric CAD (Build123d programs; ~1.3M text -> program pairs), not textured meshes; its open-weight status was not confirmed. — [Arko-T arXiv listing](https://arxiv.org/pdf/2606.30429); [besthub summary](https://www.besthub.dev/articles/a-4b-parameter-model-beats-top-ai-3d-generators-in-eight-benchmarks-f928a93d125c)
- A vendor leaderboard (Pixazo) ranks "Hunyuan3D-2.5 ... with a score of 1325, while Microsoft's TRELLIS and Meshy 5 follow" (closed-API models included; methodology not verified). — [Pixazo leaderboard](https://www.pixazo.ai/models/leaderboard/ai-3d-model-generation)

### Inferences
- For the AR-app use case, "text-to-3D" in practice means picking a text-to-image model and feeding the image to the best image-to-3D model; the native TRELLIS-text models are a fallback for quick drafts only.
- Of the open flagships, only TRELLIS.2 (MIT, no territorial/MAU clauses) is unencumbered for an app that may ship in the EU/UK; Hunyuan3D-2.1's license excludes those territories outright, which matters more than raw quality for a Unity mobile product.
- Step1X-3D and Hunyuan3D-2.1 need ~27-29 GB VRAM for shape+texture, so they are server-side only; TRELLIS.2 needs 24 GB.

- Quantitative text-to-3D benchmarks comparing TRELLIS-text-xlarge against text->image->TRELLIS-image were not found; only Microsoft's qualitative statement.
- Roblox Cube's exact license terms (commercial restrictions) could not be verified.
- Hunyuan3D-Omni's license text could not be fetched (GitHub API access was refused for that repo in this session); it is presumably a Tencent community license like 2.1 but this is unverified.

## Key Question 2: Is "text -> image (FLUX/SDXL/etc.) -> image-to-3D" the dominant practical pattern, and what evidence supports it?

### Takeaway
Yes. Microsoft's own README, Tencent's shipped text-to-3D implementation, and the ComfyUI ecosystem all implement text-to-3D as text-to-image followed by image-to-3D; the only quantitative evidence of text actually adding value comes from a CVPR 2026 paper (TIGON) that fuses text and image conditioning rather than replacing the image.

### Cited Findings
- Microsoft TRELLIS README: "It is always recommended to use the image conditioned version of the models for better performance ... Text-conditioned models are less creative and detailed due to data limitations." — [microsoft/TRELLIS README](https://github.com/microsoft/TRELLIS)
- Tencent's reference implementation of text-to-3D is literally text-to-image (HunyuanDiT v1.1 distilled) followed by image-to-3D (`image = t2i_worker(caption)` then the standard pipeline). — [Hunyuan3D-2 gradio_app.py](https://raw.githubusercontent.com/Tencent-Hunyuan/Hunyuan3D-2/main/gradio_app.py)
- SeqTex (texturing, below) also treats text conditioning by generating an image first: `system.use_generated_img_cond=true` "enables SDXL/FLUX-based image conditioning from text". — [VAST-AI-Research/SeqTex README](https://github.com/VAST-AI-Research/SeqTex)
- Nano3D's authors built their 100k editing dataset with an "image -> 3D -> edit pipeline" that "avoids render-projection entirely", i.e. text edits are applied with a 2D image editor (Qwen-Image-Lightning) and lifted to 3D by TRELLIS. — [JAMESYJL/Nano3D README](https://github.com/JAMESYJL/Nano3D)
- The TIGON paper (CVPR 2026, arXiv 2603.21295, submitted 2026-03-22) formalizes "Text-Image Conditioned 3D Generation"; it reports that "image-conditioned models achieve high visual fidelity but suffer from viewpoint bias when the input view is limited or ambiguous, while text-conditioned models provide broad semantic guidance yet lack low-level visual detail", and that "even simple late fusion of text- and image-conditioned predictions outperforms single-modality models" (search snippets; paper page blocked). — [TIGON CVPR 2026 listing](https://openaccess.thecvf.com/content/CVPR2026/html/Cen_Text-Image_Conditioned_3D_Generation_CVPR_2026_paper.html); [alphaxiv listing](https://www.alphaxiv.org/abs/2603.21295)
- The 2026 open-model round-ups describe the practical stack as a text-to-image model feeding TRELLIS 2 / Hunyuan3D ("FLUX and workflow integration mentioned ... for creating image inputs that feed into the 3D generation pipeline"; vendor/blog opinion). — [CMARIX 2026 round-up](https://www.cmarix.com/blog/top-open-source-ai-models-for-3d-image-generation/); [3D AI Studio 2026 round-up](https://www.3daistudio.com/blog/best-free-ai-3d-model-generators-2026)

### Inferences
- The text prompt's main leverage in a two-stage pipeline is at the image stage: prompt the T2I model for a clean, centered, single-object, neutral-background, 3/4-view render-style image ("3D render, white background, no shadows") because every image-to-3D model is trained on such renders. Nothing in the sources contradicts this, but it is inferred from how the datasets and demos are built.
- A second (cheap) use of text is view/semantic disambiguation: TIGON's finding implies text helps most when the single input view is ambiguous (e.g. back of the object unknown).

### Gaps
- No controlled benchmark was found comparing "text -> FLUX -> TRELLIS-image" versus "TRELLIS-text-xlarge" numerically.
- TIGON code availability is unknown (no GitHub repo found; project page https://jumpat.github.io/tigon-page could not be fetched).

## Key Question 3: Text-guided texture refinement / retexturing of an existing mesh

### Takeaway
There are open tools that take a mesh plus a text prompt (or a reference image) and write UV albedo or full PBR maps: Material Anything (MIT, PBR, text optional), SeqTex (VAST, mesh + text or image, Wan2.1-based, very heavy), Paint3D (Apache-2.0, 2K UV albedo, text or image), MVPaint and SyncMVD (text), while the production painters that ship with the flagship generators (Hunyuan3D-Paint 2.1, TRELLIS.2 shape-conditioned texturing) are image-conditioned only, so text enters through a text-to-image step.

### Cited Findings
- Hunyuan3D-Paint 2.1 (hy3dpaint) inputs: a `.glb` mesh and a `.png` reference image; outputs a textured `.glb` plus "albedo, metallic-roughness, and normal maps"; texture resolution options 512 or 768; "we recommend using a GPU with at least 21GB VRAM" for 6 views at 512; view count configurable 6-12; it is "powered by RomanTex and MaterialMVP"; custom meshes are textured by passing them to `demo.py`; no text input is documented. — [Hunyuan3D-2.1 hy3dpaint README](https://raw.githubusercontent.com/Tencent-Hunyuan/Hunyuan3D-2.1/main/hy3dpaint/README.md)
- Hunyuan3D-2.1 top-level README shows retexturing a custom mesh: `mesh_textured = paint_pipeline(mesh_path, image_path='assets/demo.png')`; "the separation of shape and texture generation ... allowing users to generate untextured meshes or apply textures to custom assets". — [Hunyuan3D-2.1 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1); [Hunyuan3D 2.1 paper abstract, arXiv 2506.15442](https://arxiv.org/abs/2506.15442)
- Hunyuan3D-Paint-v2-0 (1.3B, 2025-01-21) likewise accepts "mesh, image" "for texture synthesis on generated or handcrafted geometries". — [Hunyuan3D-2 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)
- TRELLIS.2 includes "shape-conditioned texture generation": "Please refer to the example_texturing.py for an example of how to generate PBR textures for a given 3D shape"; the example exports GLB with `texture_size=4096`; "The .glb file is exported in OPAQUE mode by default"; post-processing uses `decimation_target=1000000`, `remesh=True`, `remesh_band=1`; material stage takes ~1 s at 512^3, 7 s at 1024^3, 25 s at 1536^3 on an H100. No text input. — [TRELLIS.2 raw README](https://raw.githubusercontent.com/microsoft/TRELLIS.2/main/README.md)
- Material Anything (CVPR 2025 Highlight, MIT): inputs are "3D mesh objects (texture-less, albedo-only, generated, or scanned)" with "text prompts (optional, for texture generation on texture-less objects)"; outputs "albedo, roughness, metallic, and bump" maps plus "UV-space unwrapped materials"; uses "confidence masks as a dynamic switcher within the diffusion model"; dataset/rendering scripts released December 2024, Material Estimator and Material Refiner models released June 2025; runtime/VRAM not documented. — [3DTopia/MaterialAnything README](https://github.com/3DTopia/MaterialAnything)
- SeqTex (VAST + HKU, SIGGRAPH Asia 2025, arXiv 2507.04285): "end-to-end 3D texture generation method using video diffusion priors" built on Wan2.1; inputs are mesh + text prompt (optionally with SDXL/FLUX-generated image conditioning) or mesh + image; outputs UV texture maps (albedo-focused; PBR-shaded images also supported); code v1.0.0 released 2025-12-12 with checkpoint VAST-AI/SeqTex-Transformer on Hugging Face; inference "tested with 1 x NVIDIA A100 80GB GPU"; training needs 8x80 GB GPUs ("4 nodes to train for 1 week"). — [VAST-AI-Research/SeqTex README](https://github.com/VAST-AI-Research/SeqTex); [SeqTex abstract](https://arxiv.org/abs/2507.04285v1)
- Paint3D (CVPR 2024, Apache-2.0, code released 2024-04-26): "untextured 3D meshes + text prompts or reference images" -> "high-resolution, lighting-less, and diverse 2K UV texture maps"; built on Stable Diffusion 1.5 with depth and inpainting ControlNets plus custom UV-position / UV-inpainting / UVHD models; coarse-to-fine pipeline. — [OpenTexture/Paint3D README](https://github.com/OpenTexture/Paint3D)
- MVPaint (CVPR 2025): mesh + text prompt -> "high-resolution, seamless textures" in UV space with "minimal Janus artifacts"; three modules (Synchronized Multi-view Generation, Spatial-aware 3D Inpainting, UV Refinement); built on "MVDream, SyncMVD and Paint3D"; "a preliminary version was released July 29, 2025", models on Dropbox; license not stated in README. — [3DTopia/MVPaint README](https://github.com/3DTopia/MVPaint); [MVPaint arXiv 2411.02336](https://arxiv.org/abs/2411.02336v1)
- SyncMVD: text-to-texture for a 3D object by sharing "the denoised content among different views in each denoising step to ensure texture consistency and avoid seams"; official code at LIU-Yuxin/SyncMVD. — [LIU-Yuxin/SyncMVD](https://github.com/LIU-Yuxin/SyncMVD)
- UniTEX (CVPR 2026, Apache-2.0): mesh + reference image (text not mentioned); two-stage "Texture Functions (TFs)" volumetric representation plus a "transformer-based Large Texturing Model (LTM)" with FLUX adapted via LoRA; aims to "bypass the limitations of UV mapping"; code partially available, "full LTM checkpoint release pending". — [YixunLiang/UniTEX README](https://github.com/YixunLiang/UniTEX)
- TexPro (arXiv 2410.15891): text-prompted procedural PBR materials for an input mesh ("first generates multi-view reference images ... then derives texture maps through rendering-based optimization with ... differentiable procedural materials"), enabling relighting. — [TexPro arXiv](https://arxiv.org/abs/2410.15891v1)
- Paint-it: "text-driven, high-fidelity physically-based rendering texture synthesis on 3D meshes that directly produces full sets of PBR texture maps (diffuse, roughness, metalness, normal)" (search snippet). — [Paint-it topic page](https://www.emergentmind.com/topics/paint-it)
- A June 2026 survey, "Advances in Neural 3D Mesh Texturing: A Survey" (arXiv 2606.00137), exists and categorizes Paint3D / SyncMVD / MVPaint as 2D and 2D+UV diffusion approaches (only the listing was accessible). — [survey arXiv listing](https://arxiv.org/pdf/2606.00137)
- Ink3D (arXiv 2607.01222, July 2026): "Sculpting 3D Assets with Extremely Complex Textures via Video Generative Models" (title only; content not accessible). — [Ink3D arXiv listing](https://arxiv.org/pdf/2607.01222)
- Vendor comparison (treat as opinion): "TRELLIS.2-4B is noted as best for production-grade PBR assets, while Hunyuan3D 2.1 is best for high-fidelity textures"; "Hunyuan 3D supports textures up to 8K resolution ... it shows on close-up renders". — [3D AI Studio comparison](https://www.3daistudio.com/blog/trellis-2-vs-hunyuan-3d-differences-explained)
- Closed comparison point: Meshy 5 Retexture "applies new, high-quality textures to existing 3D models using either text prompts or reference images with support for PBR material generation". — [fal.ai Meshy v5 retexture](https://fal.ai/models/fal-ai/meshy/v5/retexture)

### Inferences
- The most practical open "text retexture" recipe today is: keep the image-to-3D mesh, generate a new reference image from the text prompt (FLUX/SDXL/Qwen-Image, ideally img2img from a render of the mesh so silhouette matches), then run Hunyuan3D-Paint 2.1 (PBR, 21 GB) or TRELLIS.2 example_texturing.py (PBR, 24 GB, seconds) on the existing mesh. This is exactly how SeqTex implements its own text mode.
- True text-native open texturing (Material Anything, Paint3D, MVPaint, SyncMVD) is research-grade: SD1.5/SDXL-era quality, no runtime figures published, and (except Material Anything) albedo-only; SeqTex is the strongest but needs an 80 GB GPU.
- For Unity mobile AR, Hunyuan3D-Paint 2.1 and TRELLIS.2 are the only open painters that emit metallic-roughness + normal maps in a GLB that Unity's glTF importers consume directly; the others would need a baking step.

### Gaps
- No published runtime numbers for Hunyuan3D-Paint 2.1, Material Anything, Paint3D, MVPaint, SeqTex inference.
- Could not fetch: TEXTure, Text2Tex, TexGen, TexGaussian, TextureDreamer, MaterialMVP, RomanTex, TexVerse standalone repos; these were only seen as citations (RomanTex and MaterialMVP are the published basis of Hunyuan3D-Paint 2.1).
- Whether TRELLIS.2's texturing stage can take a *different* image than the one that produced the mesh (i.e. true retexturing) is implied by example_texturing.py but not explicitly documented.

## Key Question 4: Text-guided geometry editing of an existing 3D asset

### Takeaway
Since mid-2025 a cluster of methods edits assets natively in TRELLIS's structured-latent space; the most usable open ones are Steer3D (feed-forward, image + text instruction, code and weights released, Dec 2025), Nano3D (training-free, text instruction applied by Qwen-Image to the front view then lifted by TRELLIS; MIT; needs ~60 GB VRAM), and VoxHammer (training-free inversion with a 3D mask); Hunyuan3D-Omni adds geometric controls (point cloud, voxel, bbox, pose) but no text. All are research-maturity; nothing is integrated into ComfyUI or Blender yet as far as I could find.

### Cited Findings
- VoxHammer (arXiv 2508.19247, Aug 2025): "a novel training-free approach that performs precise and coherent editing in 3D latent space. Given a 3D model, VoxHammer first predicts its inversion trajectory and obtains its inverted latents and key-value tokens at each timestep. Subsequently, in the denoising and editing phase, the method replaces the denoising features of preserved regions with the corresponding inverted latents and cached key-value tokens"; introduces Edit3D-Bench ("hundreds of samples, each with carefully labeled 3D editing regions"); project page https://huanngzh.github.io/VoxHammer-Page/ (blocked). The exact base generator and edit-prompt modality could not be verified from accessible sources (search snippets only). — [VoxHammer arXiv listing](https://arxiv.org/abs/2508.19247)
- Nano3D (arXiv 2510.15019, submitted 2025-10-16; accepted ICLR 2026; MIT): "integrates FlowEdit into TRELLIS to perform localized edits guided by front-view renderings, and further introduces region-aware merging strategies, Voxel/Slat-Merge"; supports "removal, addition, and replacement, while only requiring users to provide source 3D objects and instructions, without any mask"; README requires setting up TRELLIS and "Qwen-Image-Lightning" with specific LoRA weights for the 2D edit, "torch >= 2.5.1", and "At least 60GB GPU VRAM" for the Qwen-Image step; releases Nano3D-Edit-100k ("over 100,000 high-quality 3D editing pairs"). The README's own release dates read "April 2, 2025" (v1 code + dataset) and "August 5, 2025" (v2) which predate the paper; likely 2026 typos or extraction error, unverified. — [JAMESYJL/Nano3D README](https://github.com/JAMESYJL/Nano3D); [Nano3D arXiv listing](https://arxiv.org/abs/2510.15019v1); [ICLR 2026 listing](https://mlanthology.org/iclr/2026/ye2026iclr-nano3d/)
- Steer3D, "Feedforward 3D Editing via Text-Steerable Image-to-3D" (arXiv 2512.13678, Dec 2025, Caltech): "augmenting image-to-3D models with text steerability, designing a feedforward model that generates a new asset which follows the text instruction while being faithful to the 'unsteered' generation of the image-to-3D model"; "ControlNet architecture adapted to image-to-3D generation, choosing TRELLIS as the base model"; supports texture modification, geometry removal, geometry addition; inputs are a single image plus an instruction such as "Remove the entire bottom base" or "Turn the entire cone into metallic silver texture"; trained on "100k-scale synthetic data generated by our data engine" with two stages (geometry, then texture) and optional DPO; claimed "2.4x to 28.5x faster" than competing editors; code on GitHub, weights on Hugging Face, Edit3D-Bench on Hugging Face; license not specified; note: "the stage 1 base model checkpoint we use is different from the TRELLIS-released checkpoint". — [ziqi-ma/Steer3D README](https://github.com/ziqi-ma/Steer3D); [Steer3D arXiv listing](https://arxiv.org/abs/2512.13678v1); [Edit3D-Bench dataset](https://huggingface.co/datasets/ziqima/Edit3D-Bench)
- Easy3E, "Feed-Forward 3D Asset Editing via Rectified Voxel Flow" (arXiv 2602.21499, Feb 2026, CVPR 2026): "performs both geometric and appearance editing directly in TRELLIS's sparse voxel latent space, introducing Voxel FlowEdit"; edits "from a single editing view" in "a single pass"; no public code found. — [Easy3E CVPR 2026 listing](https://openaccess.thecvf.com/content/CVPR2026/html/Hu_Easy3E_Feed-Forward_3D_Asset_Editing_via_Rectified_Voxel_Flow_CVPR_2026_paper.html); [Easy3E arXiv](https://arxiv.org/abs/2602.21499)
- Other 2025-2026 TRELLIS-latent editors found only as listings: 3D-LATTE "Latent Space 3D Editing from Textual Instructions" (arXiv 2509.00269, Sep 2025); "Native 3D Editing with Full Attention" (arXiv 2511.17501, Nov 2025, "built upon the TRELLIS architecture"); MorphAny3D (arXiv 2601.00204, Jan 2026); "Velocity-Space 3D Asset Editing" (arXiv 2605.07385, May 2026); PartFlow, "Feedforward 3D Editing Learns from Semantic-Part Transformation" (arXiv 2605.27351, May 2026, "source-latent controlled 3D editing model built on the two-stage TRELLIS representation"). — [3D-LATTE](https://arxiv.org/pdf/2509.00269); [Native 3D Editing](https://arxiv.org/pdf/2511.17501); [MorphAny3D](https://arxiv.org/pdf/2601.00204); [Velocity-Space editing](https://arxiv.org/pdf/2605.07385); [PartFlow](https://arxiv.org/html/2605.27351v5)
- Hunyuan3D-Omni (released 2025-09-25, 3.3B, built on Hunyuan3D 2.1): "In addition to images, it accepts point clouds, voxels, bounding boxes, and skeletal pose priors as conditioning signals"; one unified cross-modal architecture with "progressive, difficulty-aware sampling"; "It takes 10 GB VRAM for generation"; text is not a control modality; README does not describe iterative editing. — [Tencent-Hunyuan/Hunyuan3D-Omni README](https://github.com/Tencent-Hunyuan/Hunyuan3D-Omni); [Hunyuan3D-Omni arXiv](https://arxiv.org/abs/2509.21245v1)
- TRELLIS (v1) supports "generating variants of the same object or local editing of the 3D asset" (released with the 03/25/2025 text models). — [microsoft/TRELLIS README](https://github.com/microsoft/TRELLIS)
- Older optimization-based editors (Instruct-NeRF2NeRF, Control4D) are implemented in threestudio (Apache-2.0), whose last listed update is August 2024. — [threestudio README](https://github.com/threestudio-project/threestudio)
- "Text-guided Controllable Mesh Refinement for Interactive 3D Modeling" (arXiv 2406.01592) exists as a title in results; content not accessible. — [arXiv listing](https://arxiv.org/pdf/2406.01592)

### Inferences
- Every practical 2025-2026 editor is a TRELLIS-v1 plug-in; none targets Hunyuan3D-2.1 or TRELLIS.2 latents yet. If the AR pipeline standardizes on TRELLIS (v1 or, later, .2), it keeps the door open for text editing; a Hunyuan-only pipeline would need Hunyuan3D-Omni's geometric controls instead.
- A workable text-edit loop today: render the front view of the image-to-3D asset -> edit the render with an instruction-following image editor (Qwen-Image-Edit, FLUX Kontext) -> re-run image-to-3D, optionally with Nano3D's merge to preserve untouched regions. Nano3D's dataset was built exactly this way, which signals the authors consider it the most consistent route.
- Steer3D is the only method that is both feed-forward (fast) and ships weights; its reliance on a non-standard stage-1 checkpoint is a reproducibility risk to test early.

### Gaps
- Runtime and VRAM for Steer3D, VoxHammer and Easy3E were not published in accessible sources; Nano3D's 60 GB requirement comes from the Qwen-Image component, not TRELLIS itself.
- VoxHammer's code repository URL could not be confirmed (github.com/huanngzh/VoxHammer returned 404; project page blocked).
- No evidence that any of these editors is wrapped in ComfyUI-3D-Pack, ComfyUI-Hunyuan3DWrapper, or a Blender add-on.
- GaussianEditor, MVEdit, Tailor3D, Instant3dit, Vox-E, CMD were not re-verified in this pass (older, 2023-2024 works).

## Key Question 5: Multimodal / joint image+text conditioning: does it beat image-only?

### Takeaway
The only direct evidence is TIGON (CVPR 2026), whose diagnostic study says even late fusion of text- and image-conditioned predictions beats either alone, chiefly by fixing viewpoint ambiguity; Hunyuan3D-Omni adds geometric (not text) controls, and I found no verifiable open model named Sparc3D or Seed3D with joint text+image conditioning.

### Cited Findings
- TIGON (arXiv 2603.21295, submitted 2026-03-22, CVPR 2026; authors Cen, Fang, Li, Wu, Yang, Yi, Zhou, Bao, Xie, Shen, Tian): "a minimalist dual-branch baseline with separate image- and text-conditioned backbones and lightweight cross-modal fusion"; "A diagnostic study shows that even simple late fusion of text- and image-conditioned predictions outperforms single-modality models, and extensive experiments demonstrate that text-image conditioning consistently improves over single-modality methods"; related work it names: TRELLIS and "UniLat3D ... a unified-latent variant with a simplified sampling process". Project page https://jumpat.github.io/tigon-page; no GitHub repository found. — [alphaxiv listing](https://www.alphaxiv.org/abs/2603.21295); [CVPR 2026 poster](https://cvpr.thecvf.com/virtual/2026/poster/36999)
- Hunyuan3D-Omni unifies image + {point cloud, voxel, bounding box, skeleton pose} in "a single cross-modal architecture" rather than separate heads; text is not among the controls. — [Hunyuan3D-Omni README](https://github.com/Tencent-Hunyuan/Hunyuan3D-Omni)
- Step1X-3D exposes controllability through "direct transfer of 2D control techniques (e.g., LoRA)" on its 3D-native DiT, not through text. — [Step1X-3D README](https://github.com/stepfun-ai/Step1X-3D)
- TRELLIS v1 added multi-image conditioning on 12/18/2024 (several views of the same object), which is the image-side alternative to text disambiguation. — [microsoft/TRELLIS README](https://github.com/microsoft/TRELLIS)

### Inferences
- Joint conditioning is still a 2026 research result without released production weights; for a shipping pipeline, the achievable substitutes are multi-image conditioning (TRELLIS multi-image, Hunyuan3D-2mv) and Omni's point-cloud/bbox controls, with text used upstream to generate or edit the reference image.
- Hunyuan3D-Omni's point-cloud control is the most direct open way to "refine" an existing coarse mesh: sample points from the image-to-3D mesh and regenerate with Omni so geometry is constrained while the image fixes appearance; this usage is inferred, not documented.

### Gaps
- No numbers from TIGON (the paper PDF was inaccessible), and no code.
- Sparc3D and Seed3D: no accessible open-weight repos found; cannot confirm they exist as open joint-conditioned models.

## Key Question 6: SDS / optimization-based refinement of a feed-forward result in 2025-2026

### Takeaway
Coarse-to-fine SDS refinement (Magic3D-style NeRF -> DMTet, BoostDream, DreamMesh, UniDream) is well documented through 2024, but the maintained tooling (threestudio) stopped updating in August 2024, no 2025-2026 open release couples SDS refinement to TRELLIS/Hunyuan outputs, and the field has moved to feed-forward latent editors; SDS remains a research option costing tens of minutes to hours per asset on 6-30 GB GPUs.

### Cited Findings
- threestudio (Apache-2.0) implements DreamFusion, Magic3D, ProlificDreamer, HiFA, Latent-NeRF, Fantasia3D, TextMesh, SJC, SDI for text-to-3D; Zero-1-to-3, Magic123, Stable Zero123 for image-to-3D; InstructNeRF2NeRF and Control4D for editing; extensions include MVDream, Gaussian Splatting, 4D-fy, GaussianDreamer. "Magic123 supports coarse-to-refine pipeline with DMTet conversion", "Magic3D enables NeRF coarse stage to DMTet refinement", and "Mesh initialization available for Fantasia3D via `system.geometry.shape_init=mesh`". Typical VRAM 6 GB (SD configs) to 30 GB (DeepFloyd IF full resolution); "Training typically involves 10,000+ iterations"; latest listed addition is August 2024 ("Score Distillation via Reparametrized DDIM ... 1.5x slower training"). — [threestudio README](https://github.com/threestudio-project/threestudio)
- BoostDream (IJCAI 2024, arXiv 2401.16764): "feed-forward generation solutions capable of swiftly producing 3D assets but often yielding coarse results, and Score Distillation Sampling (SDS) based solutions known for generating high-fidelity 3D assets albeit at a slower pace. BoostDream is a highly efficient plug-and-play 3D refining method designed to transform coarse 3D assets into high-quality"; uses "3D model distillation and a novel multi-view SDS loss which utilizes a multi-view aware 2D diffusion model". Runtime figures not accessible. — [BoostDream IJCAI 2024](https://www.ijcai.org/proceedings/2024/598); [arXiv listing](https://arxiv.org/html/2401.16764v2)
- DreamMesh (arXiv 2409.07454, Sep 2024): "coarse-to-fine scheme. In the coarse stage, the mesh is first deformed by text-guided Jacobians and then ... textures the mesh with an interlaced use of 2D diffusion models in a tuning free manner from multiple viewpoints. In the fine stage, DreamMesh jointly manipulates the mesh and refines the texture map". — [DreamMesh arXiv](https://arxiv.org/pdf/2409.07454)
- UniDream (arXiv 2312.08754): "After acquiring the triplane-NeRF representation of the 3D model, it is further refined using score distillation sample (SDS)", producing relightable (albedo/normal) assets. — [UniDream arXiv](https://arxiv.org/pdf/2312.08754)
- A 2024 "Quantitative Evaluation of Score Distillation Sampling Based Text-to-3D" (arXiv 2402.18780) exists; 2025 SDS work continues on the loss itself (e.g. "Linearized Lookahead Variational Score Distillation", arXiv 2507.09748; "AnchorDS", arXiv 2511.11692) rather than on refining feed-forward outputs. — [SDS evaluation](https://arxiv.org/pdf/2402.18780); [L2-VSD](https://arxiv.org/pdf/2507.09748); [AnchorDS](https://arxiv.org/pdf/2511.11692)
- ComfyUI-3D-Pack (MIT; example workflows last updated 2025-06-05) lists TRELLIS, Hunyuan3D 2.1/2/1, TripoSG, PartCrafter, MV-Adapter texturing, InstantMesh, CRM, TripoSR, 3D Gaussian Splatting, etc., but no SDS refinement nodes. — [ComfyUI-3D-Pack README](https://github.com/MrForExample/ComfyUI-3D-Pack)

### Inferences
- SDS refinement of a TRELLIS/Hunyuan mesh is feasible in principle (threestudio's Fantasia3D `shape_init=mesh` or Magic3D DMTet stage can start from a mesh), but it costs 10k+ optimization steps (tens of minutes to hours per asset), reintroduces SDS artifacts (over-saturation, smoothing), and no one has published a 2025-2026 recipe for it. For a mobile AR asset pipeline it is not worth it versus a faster retexture (Hunyuan3D-Paint 2.1 / TRELLIS.2 texturing) or a feed-forward edit (Steer3D).
- The 2025-2026 replacement for "coarse-to-fine" is resolution scaling inside the feed-forward model itself (TRELLIS.2 512^3 -> 1536^3 in 3-60 s).

### Gaps
- No wall-clock numbers for BoostDream, DreamMesh or threestudio refine stages were accessible.
- No report (paper, blog, or community) of anyone SDS-refining a TRELLIS.2 or Hunyuan3D-2.1 output was found.

## Key Question 7: Practical recipes and tooling (ComfyUI, Blender, Unity hand-off)

### Takeaway
The de-facto open recipe is text -> T2I image -> shape model -> paint model -> GLB, available as ComfyUI graphs (Comfy core Hunyuan3D 2.1 template, kijai's ComfyUI-Hunyuan3DWrapper, ComfyUI-3D-Pack with TRELLIS) and as a Blender add-on backed by the Hunyuan3D API server; text-based retexturing in Blender is served by SD-projection add-ons (Dream Textures) rather than by the 3D-native painters.

### Cited Findings
- ComfyUI's Hunyuan3D 2.1 workflow: "load an image, process it through the Hunyuan3D node, and export a GLB file"; the core nodes end with `VAEDecodeHunyuan3D` producing a voxel representation and `VoxelToMesh`; advanced graphs include "multi-view generation, baking, inpainting, and final export". — [RunComfy Hunyuan3D 2.1 workflow](https://www.runcomfy.com/comfyui-workflows/hunyuan3d-2-1-comfyui-workflow-professional-3d-asset-creation); [AMD ROCm docs: Hunyuan3D 2.1 template](https://rocm.docs.amd.com/projects/comfyui/en/docs-26.04/how-to/hunyuan3d-workflow.html); [comfy.org template](https://www.comfy.org/workflows/04_hunyuan_3d_2.1_subgraphed-5a5ed13cd1a3)
- kijai/ComfyUI-Hunyuan3DWrapper implements "image -> shape -> paint -> GLB" with mesh-processing and vertex-inpainting nodes; 207 commits; provides prebuilt wheels for "Windows 11 python 3.12 torch 2.6.0 + cu126"; no text-to-3D nodes. — [ComfyUI-Hunyuan3DWrapper](https://github.com/kijai/ComfyUI-Hunyuan3DWrapper)
- ComfyUI-3D-Pack (MIT): supports TRELLIS, Hunyuan3D 2.1/V2/V1, TripoSG, PartCrafter, MV-Adapter (incl. a texturing mode "for applying multi-view grid images to meshes"), Stable3DGen, Unique3D, Era3D, Zero123++, Wonder3D, LGM, InstantMesh, CRM, TripoSR, 3DGS, FlexiCubes; example workflows "Last update: 5/June/2025". — [ComfyUI-3D-Pack](https://github.com/MrForExample/ComfyUI-3D-Pack)
- Hunyuan3D-2 Blender add-on: "With an API server launched, you could also directly use Hunyuan3D 2.0 in your blender with our Blender Addon"; it "communicates with a locally-hosted FastAPI server to perform shape generation and texture synthesis". — [Hunyuan3D-2 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2); [Hunyuan3D-2 readthedocs: Blender](https://hunyuan3d-2.readthedocs.io/en/latest/started/blender.html)
- Dream Textures (carson-katri) for Blender supports "Project Dream Texture" with depth-to-image: "depth-based texture mapping, allowing you to automatically apply a texture to an existing 3D scene"; multiple community forks exist; maintenance status in 2025-2026 is not clearly documented. — [Dream Textures TEXTURE_PROJECTION doc](https://github.com/carson-katri/dream-textures/blob/main/docs/TEXTURE_PROJECTION.md); [blender-addons.org entry](https://blender-addons.org/dream-textures/)
- A "diffused-texture-addon" for Blender integrates diffusers with SD1.5/SDXL for Text2Image and Image2Image texturing on meshes. — [diffused-texture-addon](https://www.sourcepulse.org/projects/26341409)
- Hunyuan3D-2.1 README lists ComfyUI and Unity among community integrations (per the fetched summary), but no official Unity plugin was found. — [Hunyuan3D-2.1 README](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)
- TRELLIS.2 exports GLB with PBR maps (`texture_size=4096`, opaque by default); TRELLIS.2 post-processing offers `decimation_target` and remeshing. — [TRELLIS.2 raw README](https://raw.githubusercontent.com/microsoft/TRELLIS.2/main/README.md)
- Hunyuan 3D 3.0 is reachable from ComfyUI only via partner (API) nodes supporting "text-to-3D generation, image-to-3D generation, and multi-view-to-3D generation". — [ComfyUI docs](https://docs.comfy.org/tutorials/partner-nodes/hunyuan3d/hunyuan3d-3-0)

### Inferences
- Recommended open pipeline for the Unity AR app (server-side GPU, 24 GB+): (1) text or user photo -> optional T2I/edit step (FLUX/Qwen-Image) to get a clean reference; (2) TRELLIS.2 (MIT) or Hunyuan3D-2.1 (license-restricted) image-to-3D; (3) if the user wants a style/material change, generate a new reference image from the text prompt and re-run the painter on the same mesh (TRELLIS.2 example_texturing.py or Hunyuan3D-Paint 2.1); (4) if the user wants a shape change, Steer3D (image + instruction, feed-forward) on the TRELLIS path, else re-generate from an edited image; (5) decimate and bake to a 1-2K GLB for mobile, convert to USDZ for iOS AR Quick Look.
- Texture size: TRELLIS.2's 4096 px default and Hunyuan's 8K claims are far above mobile AR budgets; the pipeline should downsample during export rather than at generation.

### Gaps
- Stable Projectorz (stableprojectorz.com) was blocked and no reliable secondary description was found, so its current features/pricing are unverified.
- The tspi.at (2026-05-01) practitioner write-up "A Local Image/Text to 3D Solution: Hunyuan3D" was blocked; its runtime/quality observations could not be captured.
- No Reddit/Discord practitioner threads were retrievable; the only "community" quality opinions found are vendor blogs (3D AI Studio, CMARIX, Pixazo), which should be weighted accordingly.
- No open tool was found that produces USDZ directly; USDZ conversion (e.g. via Blender or usd tools) is assumed but not researched here.
